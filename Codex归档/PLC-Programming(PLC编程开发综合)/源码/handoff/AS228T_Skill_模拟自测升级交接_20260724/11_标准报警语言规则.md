# 标准报警语言规则

## 1. 推荐格式

```text
[对象] + [异常现象] + [必要的动作/恢复提示]
```

文字应让操作员知道“哪里、发生什么、下一步做什么”，避免只写“异常”“错误”“失败”。

## 2. 命名规则

- 先写设备或工位：`1轴`、`工位3推料气缸`、`机器人`、`后站`。
- 再写异常：`伺服报警`、`伸出不到位`、`通信超时`、`信号矛盾`。
- 必要时增加恢复提示：`请检查气压和感应器`、`故障消除后复位`。
- 报警文本不写程序变量名和内部地址。
- 同一对象的同类报警采用一致词汇。

## 3. 推荐示例

- `1轴伺服未就绪，请检查驱动器状态`
- `1轴正向限位触发，禁止继续正向运动`
- `1轴回原点超时，请检查原点感应器和运动方向`
- `工位3推料气缸伸出不到位，请检查气压、阀和伸出感应器`
- `工位3推料气缸伸出与缩回信号同时有效`
- `机器人EtherNet/IP通信中断，已禁止新循环`
- `后站响应超时，请检查联机状态`
- `CANopen节点4心跳超时，轴命令已撤销`
- `自动运行条件不满足，请检查安全、原点和设备状态`
- `参数校验失败，未应用伺服参数`

## 4. 不推荐示例

- `报警1`
- `设备异常`
- `动作失败`
- `D204.0错误`
- `FB_Vlv_03 Timeout`
- `请复位`（没有说明故障是否已消除）

## 5. 报警表必填字段

- 报警 ID。
- Active 地址。
- Latched 地址。
- 等级。
- 对象/工位。
- 触发条件。
- 检出延时。
- PLC 响应。
- HMI 中文文本。
- 故障排查提示。
- 复位许可。
- 恢复策略。
- 软件模拟用例 ID。
- 现场验证 ID。

## 6. 复位语言

若故障仍存在，应显示原因而不是简单拒绝：

- `1轴伺服报警仍存在，无法复位`
- `推料气缸到位信号矛盾，无法复位`
- `机器人通信未恢复，无法启动自动运行`

阀功能块普通动作过程不直接生成报警文本；只有有限重试耗尽产生诊断事件，由集中报警模块转换为标准报警。
