# 已确认规则与现状

## 1. 项目确认门禁

- 不允许收到需求后一次性生成完整程序。
- G0～G7 依次确认：项目范围、需求、I/O/地址、结构、流程、报警/接口、交付格式、最终生成授权。
- 每一阶段必须生成确认文件。
- 上游确认内容变化时，受影响的下游确认文件作废并重新确认。
- 最终交付为：`全局变量.csv`、`局部变量.csv`、按确认 POU 拆分的 `.st` 文件。

## 2. 变量排序

功能块输入固定顺序：

1. 程序状态：默认先有 `bAutoMode`、`bSequenceRunning`。
2. 伺服状态。
3. 感应器状态。
4. 设置类参数。

功能块输出固定顺序：

1. 流程号。
2. 状态。
3. 报警。
4. 伺服驱动。
5. 气缸动作。
6. 联机交互。

局部变量最后声明。全局和局部 CSV 也应保持统一、可审查的排序。

## 3. 程序整体框架

- `Prog0_Main`：按钮输入、模式切换、设备一键启动、状态/原点完成条件和周期数据。
- `Prog1_AutoSequence`：回流线、离子风/抽气及各工位自动流程。
- `Prog2_Alarm`：集中报警判断、Active/Latched、复位许可。
- `Prog3_ModuleAndOutput`：设备功能块、阀、轴和最终单一所有者输出映射。
- `Prog4_HMIManual`：轴选择、回零/旋转模式、各工位手动动作及安全解锁。
- 最终输出映射必须在全部自动和手动请求计算完成后执行。

## 4. 顺控和暂停

- 非自动状态：流程号 `-1`。
- 进入自动：流程号置 `0`。
- `0～99`：复位、初始化、回零检查和准备。
- 生产步骤从 `100` 开始，通常每次加 `10`，方便插入。
- 尽量少用 `SET/RST`，动作请求集中在流程末尾按步骤、模式、许可和联锁计算。
- 暂停保留当前逻辑步骤。
- 暂停时轴/运动请求不保持。
- 暂停时阀的逻辑状态按确认的机械安全要求保持，但仍受最终许可和安全条件限制。
- 下一步为真实执行器动作或脉冲时，前一步跳转必须检查本机运行中条件。
- 单纯联机交互信号不受本机运行中条件阻断，暂停期间继续采集和锁存，避免错过对方信号。

## 5. 阀功能块

- 每个阀使用独立驱动功能块。
- 顺控和手动逻辑只写动作请求。
- 普通阀动作逻辑内不写报警。
- 只有明确配置的有限次数重试耗尽，阀功能块才输出 `RetryExhausted` 等诊断事件。
- Active/Latched 报警由集中报警模块负责。

## 6. 地址规则重点

- `D10.0～D19.15`：系统状态。
- `D20.0～D59.15`：HMI 操作。
- `D100～D199`：伺服参数工作缓存，禁止分配其他用途。
- `D200.0～D263.15`：物理 DI 镜像。
- `D264.0～D327.15`：物理 DO 逻辑请求。
- `D400.0～D499.15`：报警 Active。
- `D500.0～D599.15`：报警 Latched。
- `D700～D799`：顺控步骤和状态机上下文。
- `D1000～D1399`：20 轴运行接口，每轴 20 字。
- `D20000～D20799`：20 轴永久参数，每轴 40 字。
- `D24000～D24999`：CANopen/HWCONFIG 输入自动映射。
- `D25000～D25999`：CANopen/HWCONFIG 输出自动映射。
- `D24000～D29999` 禁止手工变量占用；必须以实际 HWCONFIG 自动分配结果为准。

详细字段以 `AS228T_通用IO地址分配标准_送审版_v0.4.xlsx` 和 Skill 中的 `references/io-addressing-standard.md` 为准。

## 7. 联机方式

- 支持“前站主动出料、后站接收”和“后站主动取料、前站释放/定位”两类握手。
- 信号采用保持到确认或命令序号/回显，避免单扫描脉冲。
- EtherNet/IP 必须明确 Produced/Consumed 方向、Assembly、RPI、字节序、超时和失效值。
- 离散 I/O 必须记录常态、有效电平、断线状态和滤波时间。
- 通信中的 `SafetyOK` 只能作普通状态监视，不能代替急停、门锁、STO 或安全 PLC。
