# Delta AS228T-A Skill 长期研究与升级计划

> 范围固定：Delta AS228T-A + ISPSoft 3.19及以上 + ST。裸写AS228T按AS228T-A处理。  
> 执行原则：每轮只研究一个主题，优先官方资料，形成可验证的小版本，不一次性堆入大量内容。

## 一、固定资料来源

按以下优先级查找，低级来源不得覆盖高级来源：

1. 台达全球下载中心：`https://downloadcenter.deltaww.com`
2. 台达官方文件中心：`https://filecenter.deltaww.com`
3. 台达 AS 系列产品页和规格页：`https://landing.deltaww.com`
4. 台达官方 FAQ / Application Note：`https://www.deltaww.com/*/service-support/faq/`
5. ISPSoft 自带 Help、版本说明、HWCONFIG 帮助和已安装软件界面
6. AS228T-A 实际铭牌、固件、ISPSoft 项目、HWCONFIG、接线图和在线诊断记录
7. 实际使用的扩展模块、伺服、变频器、HMI 官方说明书
8. 社区、论坛和视频只用于发现关键词，不作为 Skill 事实依据

### 访问规则

- 遇到台达下载条款时，保留官方链接并要求正常接受条款，不绕过访问控制。
- 遇到过期 TLS 证书时，不使用 `-k` 或关闭证书校验。
- 不把完整官方 PDF 打进 Skill；只保存精炼结论、版本、章节和官方入口。
- 同一事实出现冲突时，实际项目/型号 > 新版型号手册 > 新版系列手册 > ISPSoft 帮助 > FAQ > 社区线索。

## 三、单批次执行模板

每个研究批次按以下步骤完成：

1. 锁定一个问题域和 1–3 份官方资料。
2. 记录资料标题、版本日期、适用型号、章节、URL 和访问状态。
3. 提取仅对 AS228T 有用的事实，标注系列级/型号级/固件级。
4. 与现有 Skill 查重并检查冲突、过时规则和 DVP 污染。
5. 更新最窄的 `references/` 文件，不把细节堆入 `SKILL.md`。
6. 增加至少一个正常案例、一个错误路由案例、一个安全边界案例。
7. 检查内部引用、外链域名、文件长度、危险动作和可执行文件。
8. 生成版本号、发布说明、SHA-256 和版本化 ZIP。

## 四、版本规则

采用语义化版本 `MAJOR.MINOR.PATCH`：

- MAJOR：改变 Skill 范围、触发方式、安全边界或不兼容地重组路径。
- MINOR：新增一个经过验证的知识域、设备类型、工作流或模板能力。
- PATCH：纠错、来源更新、措辞收紧、链接修复、版本/发布元数据调整。

发布要求：

- 包内 `VERSION` 必须与发布文件名和 manifest 一致。
- 当前包保留为 `package.zip`；稳定归档为 `releases/delta-as228t-plc-X.Y.Z.zip`。
- 至少保留最近一个稳定版本用于回滚。
- 未验证的研究笔记不得进入发布包。
- 安全规则只能通过明确评审升级，不能在普通资料更新中静默放宽。
