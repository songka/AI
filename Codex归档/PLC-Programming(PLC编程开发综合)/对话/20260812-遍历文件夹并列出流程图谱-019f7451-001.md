## 三、各模板当前行为规则

### 1. 设备模块

- 适用于电机、阀、加热等设备。
- 物理I/O不能写在功能块内部。
- 停止、故障、保护丢失优先于启动。
- 手动点动采用按住运行。
- 手动和自动使用同一套许可条件。
- 设备需要反馈时应增加启动反馈超时。
- 输出块只产生逻辑请求，最终Y由输出映射统一写入。

### 2. 启停/联锁

当前优先级为：

```text
停止/故障/联锁丢失/运行许可丢失
    优先于
自动模式下的启动请求
```

运行命令只能有一个所有者。

### 3. 简单步骤顺控

每个步骤必须包括：

- 当前步号
- 完成条件
- 下一步
- 超时或异常去向
- 复位分支

禁止在多个位置隐藏写入同一个步号。

### 4. 暂停/恢复顺控

- 暂停时保留当前逻辑步号。
- 暂停后不自动保留执行器输出。
- 每个扫描周期先清除动作请求，再由当前步骤重新生成。
- Abort或Fault直接退出流程。
- 恢复前重新检查运行许可。
- 暂停状态是否安全，必须根据机构和负载单独确认。

### 5. 状态机

- 每次扫描先给输出请求安全默认值。
- 故障或许可丢失进入故障状态。
- 未定义状态也进入故障状态。
- 状态只产生动作请求。
- 最终命令还要经过许可、联锁、故障和停止条件统一门控。
- 物理Y只能在一个输出POU中赋值。

### 6. 报警锁存

采用故障置位优先：

```text
报警触发存在 → 报警保持
报警源消失 + 复位请求 + 复位许可 → 清除
```

Trigger、Active、Latched、Ack、ResetReq和ResetPermissive必须分开。

### 7. 报警联锁

分别计算：

- 运行许可
- 工艺联锁
- 报警触发
- 故障锁存
- 复位许可
- 最终运行允许

报警存在时不能在同一扫描周期被复位命令清除。

### 8. 定时器/计数器诊断

固定检查顺序：

1. 使能条件
2. 复位条件
3. 完成或目标条件
4. 下游跳步逻辑
5. 重复初始化和其他写入者

### 9. 输出所有权审查

每次先选一个目标，例如Y输出、运行命令、报警位或步号，然后记录：

- 设计所有者
- 所有置位位置
- 所有清除位置
- 初始化和复位位置
- 多条件同时出现时的优先级
- 在线可能表现
- 推荐的单点所有权结构

### 10. I/O表交付

当前要求至少包含8张表：

1. 说明与规则
2. 地址分区
3. 物理DI/DO
4. 机器人接口
5. 轴与CANopen

7. HMI手动

每张表必须有生产者、唯一写入者、消费者、状态和来源字段。详见[io-table-standard-template.md](</C:/Users/lfaf-test/Documents/PLC-Programming(PLC编程开发综合)/package/templates/common/io-table-standard-template.md:1>)。

## 二、建议在生成程序时加入模拟层

如果直接用真实X、Y、CANopen和伺服状态写流程，模拟会很困难。建议增加一个全局模拟状态：

```st
gSim_Enable : BOOL;
```

输入映射采用：

```st
IF gSim_Enable THEN
    bPartSensor := gSim_PartSensor;
    bCylinderExtended := gSim_CylinderExtended;
    bAxisReady := gSim_AxisReady;
ELSE
    bPartSensor := X实际输入;
    bCylinderExtended := X实际输入;
    bAxisReady := CANopen实际状态;
END_IF;
```

设备动作仍然只产生逻辑请求：

```st
bCylinderExtendReq
bAxisMoveReq
bDownstreamAllowReq
```

模拟FB根据这些请求生成虚拟反馈：

```text
气缸伸出请求
    → 模拟延时
    → 气缸伸出到位

轴移动请求
    → 模拟Busy
    → 模拟到位
    → InPosition

前站出料完成
    → 模拟后站延时
    → 后站允许下一步
```

这样不需要模拟真实CANopen、脉冲输出或现场接线，就能检查大部分顺控逻辑。

## 三、模拟测试顺序

### 1. 初始化测试

检查：

- 非自动时流程号是否为`-1`
- 进入自动后是否变为`0`
- `0～99`是否只执行复位和准备动作
- 未满足原点、传感器和设备就绪时，能否阻止进入步骤100

### 2. 正常自动流程

按步骤逐个模拟输入：

```text
步骤100 → 满足条件 → 110
步骤110 → 动作反馈 → 120
步骤120 → 联机确认 → 130
```

确认步骤按10递增，输出由“当前步骤＋许可＋互锁”在程序末尾统一生成。

### 3. 暂停/恢复

重点验证你的规则：

- 暂停后流程号保持
- 轴运动请求立即撤销
- 阀保持当前步骤要求的状态
- 上下站联机信号仍然采集
- 恢复时重新检查轴位置、气缸反馈、互锁及联机状态
- 不会恢复后重复发送一次性动作

### 4. 报警与重试

逐项模拟：

- 气缸不到位
- 伺服报警
- 轴运动超时
- 感应器状态矛盾
- 上下站等待超时
- 通信状态无效

检查普通阀动作失败是否由中央报警模块产生报警；配置多次重试时，应在最后一次失败后才产生`RetryExhausted`。

### 5. 上下站联机

分别测试两种对接：

- 前站主动出料、后站接收
- 后站主动取料、前站松开定位

每种都要模拟：

- 正常请求/确认
- 对方延迟
- 本机暂停、对方继续
- 信号提前到达
- 信号一直保持
- 信号中途消失
- 断线后重新建立握手

### 6. 手动功能

检查：

- 手动模式才能执行
- 松开按钮立即停止点动
- 手动轴不进入自动步骤
- 手动和自动请求不会同时成立
- 手动操作仍经过互锁和设备许可

## 四、模拟器不能证明的内容

台达明确说明，模拟结果不会与真实PLC完全一致；定时器和计数器执行时间会受到电脑性能影响，最终仍须进行实机测试。[台达模拟器注意事项](https://www.deltaww.com/zh-TW/service-support/faq/635)

以下项目不能仅靠模拟器验收：

- CANopen真实PDO、SDO、Heartbeat和EMCY
- EtherNet/IP连接、Assembly、RPI和断线行为
- 脉冲输出和高速计数
- 回原点、绝对/相对定位
- 实际正反限位
- 伺服使能、STO和报警复位
- 真实传感器有效电平和断线状态
- 气缸、阀、接触器的实际动作时间
- PLC STOP、断电、保持区和重新上电行为
- 精确扫描周期、定时和运动性能

官方FAQ列出的不支持指令中包括`PLSY`、`PLSR`、`ZRN`、`DRVI`、`DRVA`等运动类指令。因此模拟阶段应模拟轴接口状态，不应把脉冲定位指令的模拟结果当作实机结论。

建议把程序验证分成四层：

1. 静态检查  
   检查变量重复、地址冲突、D100–D199占用、未赋值输出、流程跳步、报警复位条件、20轴地址越界等。

2. ST仿真层  
   生成 `FB_Simulation`，用模拟变量替代传感器、伺服和联机对象。实际 `X/Y/CANopen/EIP` 只存在于映射层。

3. ISPSoft AS200 Simulator  
   下载后运行自动测试序列，监视步骤、输出、报警和恢复。官方说明模拟器不能完整模拟运动、高速I/O和真实通信，因此这一层主要验证状态机与报警处理。

4. 现场/HIL验证  
   接AS228T-A、伺服、阀岛、机器人和安全回路，验证实际信号极性、时间、运动方向、限位、STO以及断线行为。

每个现场异常都按以下六项自动判定：

| 判定项 | 要验证的内容 |
|---|---|
| 检出 | 异常是否在规定时间内被发现 |
| 报警 | 报警代码与标准语言是否正确 |
| 动作 | 轴停止、阀保持/复位、交互信号是否符合规则 |
| 流程 | 步骤保持、退回、终止或进入恢复步骤是否正确 |
| 复位 | 异常未消除时不能复位，消除后才允许 |
| 恢复 | 复位后继续、重做当前步或重新初始化是否正确 |

必须覆盖的故障场景包括：

- 传感器：常ON、常OFF、抖动、延迟、两个到位同时成立。
- 气缸：动作超时、反向信号出现、首次不到位、重试成功、重试耗尽。
- 伺服：未Ready、报警、运行中掉Ready、正反限位、回零失败、定位超时、暂停中断。
- 通信：CANopen断线、EIP断线、数据冻结、恢复后旧命令残留。
- 联机：对方无应答、信号脉冲过短、顺序错误、重复应答、暂停期间收到信号。
- 操作：自动中切手动、互斥按钮同时按、连续启动、异常未消除强制复位。
- 流程：每一步超时、暂停/恢复、急停后恢复、初始化中途失败。
- 边界：参数为0、最大值、负值、20轴同时存在、定时器临界扫描周期。
- 掉电：流程号、报警、参数缓存、输出状态和首次扫描初始化。

