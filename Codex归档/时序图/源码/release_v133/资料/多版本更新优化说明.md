## 三、分阶段更新说明

### 1. v106—v115：从流程录入到自动输出

- 用户按动作填写流程，系统按重复次数和触发规则展开时序数据。
- 时序图预览、Excel 导出和周期汇总使用同一份排程结果，减少口径不一致。
- 输入轮数、时间和重复次数增加明确校验，非法值不再静默转换。
- Excel 逐步补充周期说明和等待动作说明，输出结果可直接被非开发人员阅读。

优化意义：建立“结构化录入—规则计算—图表展示—Excel 交付”的基础闭环。

### 2. v116—v126：复杂条件、编辑效率与双语支持

- 窗口标题显示版本号，降低多版本并存时误用旧文件的风险。
- 第一轮与后续轮可使用不同触发条件；未启用不同条件时默认继承第一轮规则。
- 动作支持插入、拖拽排序、多选删除和表格内直接编辑。
- 支持简体中文/繁体中文界面、模板和导出内容切换。
- 增加等待轮数并保留旧 Excel 导入兼容。

优化意义：让现场工程人员能表达更复杂的动作关系，同时保持编辑效率和历史数据兼容。

### 3. v127—v130：工程知识复用与使用体验

- 新增常用动作时间库，可选择固定动作或按公式计算动作时间。
- 内置伺服轴、气缸、真空吸附、破真空等工程计算。
- 公式参数支持常见单位后缀，降低重复换算和录入错误。
- 窗口按分辨率自适应，小屏自动调整工具栏、分栏和输入区。

优化意义：把个人经验转为可维护的参数与公式，推动知识标准化。

### 4. v131—v133：排程语义收敛与稳定性修复

- 绘制轮数作为有效轮次上限，超出范围的动作不再显示或参与等待。
- 等待动作只在目标轮次真实存在时生效，减少等待不存在步骤造成的误判循环。
- 重复动作在同一轮中显示为 `轮次-次数`，例如 `1-1 / 1-2 / 1-3`。
- 固定次数等待直接匹配同一轮内的目标次数，图面箭头与内部依赖一致。

优化意义：解决多轮、重复动作和跨动作依赖组合下最容易出错的边界场景。

### 5. v133 维护更新：公式编辑与 Windows 发布

- 常用动作分为“使用者”和“编辑者”入口，降低误改配置的风险。
- 支持新增、修改、删除公式动作，并维护公式、参数和说明。
- 自定义表达式支持 `if()`、`abs`、`min`、`max`、`round`、`ceil`、`floor`、`sqrt`、`pi`。
- 修复公式编辑器读取当前参数时调用已删除函数导致的 `NameError`。
- EXE 运行时把配置文件定位到 EXE 所在目录，避免单文件临时解包目录导致配置丢失。
- Windows 打包脚本采用 UTF-8 代码页、CRLF 换行和单行 PyInstaller 调用，避免中文乱码及 `scriptname required`。

优化意义：增强非开发人员的自助配置能力，并形成可直接分发的 Windows 发布包。

## 四、综合价值

### 业务价值

- 把时序关系从口头描述、截图和人工绘图转为可复用的结构化数据。
- 图、Excel、周期统计共用同一计算结果，便于评审和追溯。
- 通过模板导入、动作库和公式库降低重复劳动。

### 技术价值

- 排程、依赖解析、可视化和 Excel 输入输出相互解耦，便于持续迭代。
- 对旧表头、简繁体字段和历史配置保留兼容路径。
- 单文件 EXE 降低使用门槛，配置文件外置便于现场调整。

### 组织价值

- 将工程规则、动作时间和公式沉淀为团队资产。
- 版本记录保留每次修复的场景和验证结果，形成可审计的迭代链路。
- 项目展示了业务人员定义规则、AI 协助编码与测试、人机共同验收的协作模式。

## 五、创新性

- 不是单纯“画图”，而是先建立可计算的动作依赖模型，再同时驱动图形与 Excel。
- 把首轮条件、后续条件、等待轮数、重复次数和固定次数等待纳入统一排程语义。
- 将设备动作时间公式内置并开放自定义表达式，使工具具备轻量工程计算平台属性。
- AI 参与需求澄清、边界案例推演、代码修改、回归验证、打包与文档整理；业务规则和最终判断仍由工程人员掌握。

## 六、可拓展方向

1. 增加标准测试集：把典型设备流程固化为自动回归案例。
2. 增加版本内升级：配置文件加入 schema 版本和自动迁移。
3. 增加数据接口：支持 MES/PLC/设备日志导入，比较设计时序与实测时序。
4. 增加规则检查：识别循环等待、资源冲突、空闲瓶颈和异常周期。
5. 增加协同能力：动作模板、公式库和项目文件支持团队级共享与权限控制。
6. 增加发布治理：代码签名、安装包、自动更新和发布检查清单。
