## 二、Skill 能否进行签核动作

技术上可以让 Skill 指导 AI 调用：

```text
python auto-sign/qh.py sign approve ...
```

但不建议让 AI 自己决定并直接执行。Skill 是指令和知识包，不应成为绕过确认的签核入口。

推荐采用分层权限：

| 动作 | Skill/AI 是否可以执行 |
|---|---|
| 查询待签内容 | 可以 |
| 模拟自动签核 | 可以 |
| 测试规则 | 可以 |
| 生成建议签核指令 | 可以 |
| 实际签核、拒签 | 只准备操作，等待用户明确确认 |
| 全签、全拒 | 必须快照并二次确认 |
| AI 自行判断后签核 | 禁止 |

安全流程应是：

```text
用户要求签核
  ↓
Skill 调用只读查询
  ↓
展示申请单号和规则判断
  ↓
生成待执行指令
  ↓
用户明确确认
  ↓
确定性 CLI 执行
  ↓
重新查询平台验证
  ↓
记录统计并按策略通知
```

这样可以说“Skill 支持签核工作流”，但不是“AI 可以自行签核”。

如果改成允许 AI 直接提交，会破坏现有安全规则，也可能再次出现“模拟自动签核却真实签核”的问题。建议实现“查询和准备由 Skill 完成，最终提交由确定性 CLI 在确认后完成”。

## 二、安全规则职责

安全规则主要在两个位置。

### 1. Skill 总体安全规则

[SKILL.md](/C:/Users/lfaf-test/Documents/飞书自动签核/.agents/skills/manage-feishu-signing/SKILL.md:10) 规定：

- 修改消息路由、AI、确认和签核前必须读取安全策略；
- 修改规则或通知前必须读取规则结构；
- 修改 CLI 和用户指令前必须读取命令说明；
- 不得把账号、凭证、用户数据放进示例、日志、测试或压缩包；
- 模糊的 AI 意图只能给建议；
- 全签、全拒以及与规则相反的人工操作必须确认；
- 只有平台复查成功的动作才能写入统计；
- OAuth 网页必须按当前用户的 `open_id` 服务端隔离。

### 2. 具体签核安全规则

[safety-policy.md](/C:/Users/lfaf-test/Documents/飞书自动签核/.agents/skills/manage-feishu-signing/references/safety-policy.md:3) 规定：

- 只有确定性的明确指令可以进入操作流程，例如 `签核 1 3`；
- AI 判断出的签核或拒签意图只能转换成指令建议；
- “模拟、测试、预览、试跑”优先进入只读流程；
- “为什么、怎么、解释、说明”优先进入自然聊天；
- 全签和全拒使用申请单号快照确认；
- 确认时重新获取待签内容，只处理快照中的申请单号；
- 人工拒签原因可选，没有填写时使用匹配规则理由；
- 平台复查成功前不能发送群通知；
- 日志中不得出现密码、API Key、Token、OAuth Code 或 Cookie。

### 3. 安全规则如何进入测试

当前冒烟脚本 [smoke-test.py](/C:/Users/lfaf-test/Documents/飞书自动签核/.agents/skills/manage-feishu-signing/scripts/smoke-test.py:13) 已检查：

- AI 动作只能变成指令提示；

  "event": {

          }
        }
      ]

  }
