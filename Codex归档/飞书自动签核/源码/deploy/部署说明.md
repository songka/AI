# 签核工具箱 — 部署说明书

域名: qh.lfaf.eu.org  目录: /www/wwwroot/lfaf.eu.org/qh

## 1. 上传并安装

```bash
# 上传 deploy/ 全部文件到 /www/wwwroot/lfaf.eu.org/qh/
cd /www/wwwroot/lfaf.eu.org/qh
PY=/www/wwwroot/lfaf.eu.org/qh/.venv/bin/python
"$PY" -m pip install -r auto-sign/requirements.txt
"$PY" auto-sign/runtime_check.py
```

不要使用系统 `pip3`；CentOS 7 上它通常指向 Python 3.6。若预检显示
`OpenSSL 1.0.2`，项目会固定使用 `urllib3 1.26.x`；`urllib3 2.x` 要求
OpenSSL 1.1.1+，会导致 Gunicorn Worker 启动失败。该兼容方案仅用于迁移期，
应规划把操作系统升级到仍受支持的版本。

使用 `qh-deploy-fixed.zip` 时，默认压缩包包含 `auto-sign/`、两个运行脚本和说明文档，不包含只供本地 AI 维护使用的项目 Skill。运行期的 `feishu.json`、`config.json`、`rules.json`、`groups.json`、`users/`、`data/` 不放入更新包，避免覆盖服务器配置和用户数据。必须解压到 `/www/wwwroot/lfaf.eu.org/qh/`，解压后应存在：

```text
/www/wwwroot/lfaf.eu.org/qh/auto-sign/callback_server.py
/www/wwwroot/lfaf.eu.org/qh/run-server.sh
/www/wwwroot/lfaf.eu.org/qh/run-scheduler.sh
```

如果服务器上也需要 Codex 等 Agent 维护项目，可在本地使用
`powershell -File build-release.ps1 -IncludeSkill -ChangeRecord <已审批记录.json>`
生成包含 `.agents/` 的维护包。
Skill 不参与 Gunicorn 和飞书机器人运行。

不能解压成 `/www/wwwroot/lfaf.eu.org/qh/deploy/auto-sign/`，否则 Gunicorn 仍会加载旧代码。

重启后检查实际加载版本：

```bash
curl -s http://127.0.0.1:7000/health
```

应返回 `"version":"2026.07.30.1900"`，并包含 `"safe_ai_actions":true`。如果仍是旧版本，说明旧 Gunicorn 进程或错误目录仍在被加载。

### 机器人自定义菜单

在飞书开放平台进入当前应用的“机器人 → 自定义菜单”，添加六个事件型菜单项：

| 菜单名称 | `event_key` | 执行动作 |
|---|---|---|
| 帮助 | `help` | 展示全部指令与口语说法 |
| 查询签核内容 | `query_pending` | 查询当前用户的全部待签内容 |
| 规则 | `rules` | 打开规则管理卡片 |
| 组管理 | `groups` | 打开用户组/内容组卡片 |
| 设置 | `settings` | 打开自动签核设置卡片 |
| 统计 | `stats` | 打开当前用户的 OAuth 统计网页卡片 |

事件订阅中还需要启用“机器人自定义菜单事件”，事件类型为
`application.bot.menu_v6`，请求地址继续使用现有的 `/feishu/event`。

## 2. feishu.json 配置

复制模板并编辑：
```bash
cp auto-sign/feishu.example.json feishu.json
vi feishu.json  # 只填写非敏感配置；密钥按下方安全迁移流程写入
```

先安装依赖并按 `安全运维手册.md` 创建仓库外主密钥及
`/etc/qh/qh.env`。`run-server.sh` 与 `run-scheduler.sh` 会自动读取该文件，
宝塔启动命令和计划任务无需重复填写 `QH_MASTER_KEY_FILE`。现有部署执行
`python3 auto-sign/qh.py security migrate --root "$PWD"`，把敏感字段和用户
`auth.json` 迁移为 `secrets.enc`、`auth.enc`；新部署可由密钥平台直接注入对应
环境变量。主密钥、密文和 `.qhb` 备份都不进入发布包。

一键获取 bot_open_id：
```bash
/www/server/python_manager/versions/3.9.7/bin/python3 auto-sign/setup.py
```

（可选）设置外部 AI：
```bash
/www/server/python_manager/versions/3.9.7/bin/python3 auto-sign/qh.py feishu ai-setup
```
按提示输入 DeepSeek API Key，或直接回车跳过。不配 AI 则 AI加规则 使用内置模式匹配。

推理模型建议在 `feishu.json` 中设置 `"ai_max_tokens": 2048`、`"ai_timeout": 60`。如果服务日志出现 `[AI] content 为空`，说明输出额度被推理内容耗尽，应继续提高 `ai_max_tokens`。

| 字段 | 用途 | 获取 |
|------|------|------|
| webhook_url | 群通知 webhook | 群设置 → 机器人 |
| app_id | 飞书应用 ID | 开放平台 |
| app_secret | 飞书应用密钥 | 开放平台 |
| receive_id | 群 chat_id | `lookup --chats` |
| private_id | 管理员 open_id | 群成员 API |
| allowed_open_ids | 可选的私聊用户限制；空数组表示允许租户内所有用户 | 手工填写 open_id 数组 |
| bot_open_id | 机器人 open_id | **setup.py 自动** |
| verification_token | 校验回调确实来自飞书 | 开放平台 → 事件与回调 → 加密策略 |
| title | 通知卡片标题 | 自定义 |
| dashboard_base_url | 统计网页公开 HTTPS 地址 | 如 `https://qh.lfaf.eu.org` |
| oauth_redirect_uri | 飞书 OAuth 回调 | `https://qh.lfaf.eu.org/stats/oauth/callback` |
| dashboard_secret | 网页会话签名密钥 | 至少 32 位随机字符串 |

## 3. 宝塔 Python 项目

| 设置 | 值 |
|------|-----|
| 域名 | qh.lfaf.eu.org |
| 路径 | /www/wwwroot/lfaf.eu.org/qh/auto-sign |
| 框架 | Flask |
| 启动 | gunicorn |
| 启动命令 | `/www/wwwroot/lfaf.eu.org/qh/run-server.sh` |
| 端口 | 7000 |
| Python | 3.9.7 |
| SSL | *.lfaf.eu.org 证书 |

`run-server.sh` 从 `/etc/qh/qh.env` 加载主密钥来源，再使用同一 Python 解释器
启动 Gunicorn。修改或发布后确认脚本可执行：

```bash
chmod 750 /www/wwwroot/lfaf.eu.org/qh/run-server.sh \
  /www/wwwroot/lfaf.eu.org/qh/run-scheduler.sh
```

Gunicorn 初始保持 1 Worker、4 Threads。部署并采集至少 7 天真实指标后执行：

```bash
python3 auto-sign/qh.py ops capacity \
  --db data/stats.db --days 7 --cpu "$(nproc)" --memory-mb 2048 \
  --output data/capacity-recommendation.json
```

只有输出包含 `recommendation` 时才按证据设置 `QH_GUNICORN_WORKERS`、
`QH_GUNICORN_THREADS` 和计划任务间隔；无样本时命令返回 2，禁止猜测容量。
SQLite 已启用 WAL、`busy_timeout=15s` 和 `synchronous=NORMAL`。唯一待办写入不使用
SQLite 3.24 才支持的 UPSERT 语法，可兼容 CentOS 7 常见的 SQLite 3.7.x。建议显示
`postgresql` 时，应另开数据库迁移变更，不得在原发布中临时切换。

## 5. 计划任务

Shell → 每分钟：
```
/www/wwwroot/lfaf.eu.org/qh/run-scheduler.sh
```

宝塔会自行给每次计划任务写入 `★ Successful`，即使程序没有输出。硬盘空间紧张时，停用宝塔中的这条任务，改用系统 crontab；程序没有到期用户时不会向下列日志追加任何内容：

```bash
* * * * * /www/wwwroot/lfaf.eu.org/qh/run-scheduler.sh >>/www/wwwlogs/qh-auto.log 2>&1
```

`run-scheduler.sh` 使用 `flock`，上一轮未结束时本轮立即退出，避免计划任务重入。
它与服务启动脚本读取同一个 `/etc/qh/qh.env`；如果环境文件和外部主密钥注入都
缺失，任务会写入明确错误并退出，不再显示为无输出的静默跳过。

如需彻底丢弃包括异常在内的所有任务输出，把末尾改为 `>/dev/null 2>&1`。

网站侧在 `feishu.json` 保持 `"debug_logging": false`，并在 Nginx 站点配置中关闭正常访问日志、仅保留错误日志：

```nginx
access_log off;
error_log /www/wwwlogs/lfaf.eu.org.error.log error;
```

## 7. 飞书命令

**签核**: 查询 | 卡片 | 模拟自动签核（只读） | 执行一次自动签核（按规则单次运行） | 签核 1 3 | 拒签 2 原因:... | 全签 | 全拒 | 确认 | 取消
**账户**: 登录 | 账号:xxx 密码:xxx | 登出 | 状态
**管理中心**: 管理中心 → 规则 | 组管理 | 设置
**规则**: 规则（Card JSON 2.0，可完整编辑名称、条件、逻辑、通知及拒签理由） | 加规则 | 删规则 | 暂停规则 | 改/清除拒签理由 | AI加规则
**组**: 组管理 | 用户组 | 内容组（均在卡片新建、编辑、重命名、删除）
**设置**: 设置（卡片编辑自动签核、待手动提醒、时间、间隔、等待和群通知默认值）
**待手动提醒**: 待手动提醒 开/关（只私聊新增项；自动签核暂停时仍可运行）
**个人网页**: 统计 → 飞书 OAuth → 统计/规则/用户组与内容组/设置；按当前 open_id 隔离，修改请求带 CSRF 校验；顶部可切换简体/繁體，默认跟随最近一次飞书中文对话
**群@**: @某人+@机器人 → 以被@者身份查询。异常@对应用户。

## 8. 规则参考

动作优先级: auto_reject > auto_approve > 待手动

群通知优先级: 手动明确 > notification_rules > 动作规则 group_notify > default_group_notify（默认 false）

操作符: equals, not_equals, contains, starts_with, starts_with_any, not_starts_with, has_cn, is_empty, regex, not_regex, in_list, not_in_list, in_user_group, not_in_user_group, starts_with_content_group, not_starts_with_content_group, ends_with_content_group, not_ends_with_content_group, contains_content_group, not_contains_content_group

字段: 申请人, 描述, 类别, 单位, 申请单号

GSC 类别按原始值设置（常见 P/PH/FG）；字母单号和英文 `Applicant:` 的非料号记录会显示申请人、正文及类别 `非料号`。

## 9. 目录结构

```
users/ou_xxx/             ← 每用户自动创建
  auth.enc                ← 主密钥加密的签核平台凭证
  rules.json              ← 个人动作规则和通知规则
  groups.json             ← 多个用户组和内容组
  settings.json           ← 时间窗口/暂停/等待
sign_events.json          ← 签核事件记录（等待检测用）
data/stats.db             ← 含 open_id 的个人签核统计；网页强制按当前 OAuth 用户过滤
```

## 10. 等待签核

飞书发送 `等待设置` → 从其他已登录用户中多选 → 任意一人真实完成签核/拒签 → 记录 `sign_events.json` → 定时检查 → 30-60 秒延时 → 重新查询 → 仅按等待者当前规则运行一轮 → 清除等待设置。未命中规则的项目始终保持待手动，不提供动作选择。

## 11. 异常处理

签核失败 → 首次出现的异常在群内 @对应用户 + 原因；相同异常持续发生时不重复提醒，成功一次后才清除异常状态。

## 12. 新用户初始化

新用户首次私聊时只创建空配置：签核、拒签、通知规则为空；用户组和内容组也为空。旧名单按兼容名称映射，不会在升级时自动删除或批量改写；默认组一旦被改名或删除，就不会再次从旧名单生成。

多用户模式请保持 `"allowed_open_ids": []`。只有需要限制私聊用户时才填写，例如 `["ou_xxx", "ou_yyy"]`；`private_id` 仅表示管理员，不再阻止其他用户使用。

默认使用精简日志：`"debug_logging": false`。此模式不记录每条消息、每张成功回复或重复异常；临时排查时才改为 `true`，完成后应恢复为 `false`。

统一 CLI 的详细用法见 `飞书CLI使用说明.md` 和 `签核CLI使用说明.md`。旧版全局 `sign_records.xlsx` 因没有 open_id，只保留为历史档案，不自动导入个人统计。

## 13. 生产 KPI 与发布治理

`feishu.json` 可配置 `kpi_admin_open_ids`；`private_id` 默认也是 KPI 管理员。
管理员通过飞书 OAuth 登录后访问 `/stats/kpi`，普通用户固定返回 403。自动处理率、
待人工率、失败率和平均处理时长均来自真实唯一待办生命周期与平台复查结果。

生产打包必须提供审批通过的 Change Record：

```powershell
powershell -ExecutionPolicy Bypass -File build-release.ps1 `
  -ChangeRecord C:\approved\CHG-2026-0042.json
```

灰度、阈值判断、版本目录切换和回滚步骤见 `发布治理与回滚.md`。
