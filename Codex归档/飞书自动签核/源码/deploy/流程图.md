# 签核工具箱 — 系统流程图

按业务用户、飞书平台、签核服务、GSC 平台、AI、数据和本地维护门禁划分的主体架构，
见同目录 `系统架构分区.md`。本文件继续描述各运行流程的细节。

飞书签核系统本身的分层技术框架，见同目录 `飞书签核系统框架说明.md`；
可直接用于报告的图片为 `飞书签核系统框架图.svg`。

## 3. 定时任务流程（每分钟）

```
计划任务触发 qh.py feishu send
  │
  ▼
遍历 users/ 下所有已登录用户
  │
  ├─ 自动签核、待手动提醒、等待都关闭？ ─ 是 ─→ 跳过
  │       否（任一开启即继续查询）
  ├─ 不在个人时间窗口？ ─ 是 ──→ 跳过
  │       否
  ├─ 未到间隔时间？ ──── 是 ──→ 跳过
  │       否
  ▼
┌──────────────────────┐
│ 用该用户凭证登录 GSC   │
│ 抓取待签列表          │
│ 加载个人规则（排除暂停）│
└──────┬───────────────┘
       │
       ▼
┌──────────────────────────┐
│ 找出待手动/需要确认项目     │
│ 首次开启提醒 → 只建立基线    │
│ 后续新增项目 → 私聊增量卡片   │
│ 项目未变化 → 不重复提醒       │
│ 清单为空 → 只更新基线不通知   │
└──────┬───────────────────┘
       │
       ▼
┌──────────────────────┐
│ 检查等待条件           │
│ check_wait_for()     │
└──────┬───────────────┘
       │
  ┌────┴────┐
  │ 有人在等？│
  └────┬────┘
   是  │  否
   ▼   │   ▼
┌──────────────┐  ┌──────────────┐
│ 等的人已签完？ │  │ 规则匹配      │
│ (有签核记录)  │  │ 自动签核/拒签 │
└──┬───────────┘  └──────┬───────┘
   │是          否        │
   ▼           ▼         ▼
┌────────┐  ┌────┐  ┌──────────┐
│30-60s  │  │跳过 │  │ 执行规则  │
│随机延时│  └────┘  │ 记录事件  │
│重取数据│          │ 群通知    │
│按规则一轮│         │ @用户     │
└───┬────┘          └──────────┘
    │
    ▼
┌──────────────┐
│ 执行签核      │
│ 提交后重新查询 │
│ 仍在待签→失败  │
│ 已消失→成功通知│
│ 飞书名/登录账号│
│ 签核→绿色独立卡│
│ 拒签→红色独立卡│
│ 完整明细/拒签原因│
└──────────────┘
```

## 4. 飞书消息处理

```
飞书回调 POST /feishu/event
  │
  ├─ verification_token 校验失败 → HTTP 403 拒绝
  ├─ message_id/event_id → stats.db 认领
  │    └─ 10 分钟内重复 → 立即返回，不回复也不执行
  ├─ url_verification → 返回 challenge
  ├─ card.action.trigger → 同步执行按钮动作
  │    ├─ 暂停/恢复规则 → 更新 settings.json
  │    ├─ 删除规则 → 更新 rules.json
  │    ├─ 顶部群通知默认按钮 → 切换 default_group_notify
  │    ├─ 签核/拒签规则通知按钮 → 跟随→发群→不发群→跟随
  │    ├─ 单条规则编辑卡 → 修改名称、AND/OR、条件、通知和拒签理由
  │    ├─ 组编辑卡 → 修改组名与内容；重命名同步全部规则引用
  │    ├─ 用户组/内容组表单 → 新建、编辑、重命名、删除 groups.json
  │    │    ├─ 空组/缺失组 → 永不匹配
  │    │    └─ 被规则引用 → 拒绝删除
  │    ├─ 设置表单 → 启停、时间、间隔、等待、群通知默认值
  │    └─ 3 秒内返回 toast + 新卡片内容 → 原卡片原地刷新
  ├─ application.bot.menu_v6 → 自定义菜单
  │    ├─ event_key=help → 帮助卡片
  │    ├─ event_key=query_pending → 查询点击人的全部待签内容
  │    ├─ event_key=rules → 规则管理卡片
  │    ├─ event_key=groups → 组管理卡片
  │    ├─ event_key=settings → 设置卡片
  │    └─ event_key=stats → 当前用户 OAuth 统计网页卡片
  └─ im.message.receive_v1 → 消息处理
       │
       ├─ 私聊 (p2p)
       │    ├─ allowed_open_ids 为空 → 允许租户内用户
       │    ├─ allowed_open_ids 非空 → 仅允许名单内 open_id
       │    ├─ 登录/登出/状态
       │    ├─ 规则/加规则/删规则/AI加规则
       │    ├─ 管理中心/规则/用户组/内容组/设置 → 卡片编辑
       │    ├─ 暂停规则/暂停自动签核
       │    ├─ 设时间/等待设置/取消等待
       │    ├─ 模拟/测试/预览 → 只展示，禁止提交
       │    ├─ 查询/卡片
       │    │    └─ 全部待签 → 每5项一张卡片 → 完整字段、多页发送
       │    ├─ 明确签核 X/拒签 X → 与规则相反时二次确认
       │    ├─ 全签/全拒 → 始终按单号快照二次确认
       │    ├─ AI 判断签核/拒签 → 只提示明确指令，绝不执行
       │    ├─ 为什么/怎么/解释 → 自然聊天
       │    ├─ 统计 → 飞书 OAuth 个人网页（统计 / 规则 / 用户组与内容组 / 设置）
       │    ├─ 模拟自动签核 → 只读展示动作、真实执行后的通知判断和未命中原因
       │    ├─ 执行一次自动签核 → 当前用户按规则运行一轮，不修改定时开关
       │    └─ 帮助
       │
       └─ 群聊 (group)
            ├─ `@人员 执行一次自动签核`
            │    ├─ 无需 @机器人；只 @机器人 → 忽略
            │    ├─ 提取人员 open_id，必须已经登录
            │    ├─ 同一群 + 同一人员五分钟防抖
            │    ├─ 每个人只按自己的签核/拒签规则运行一轮
            │    └─ 平台复查成功后按该人员通知策略决定是否发群
            └─ 普通 @、问句、解释句或其他文字 → 忽略
```

### 4.1 回复展示流程

```
业务处理结果
  │
  ▼
统一 reply()
  │
  ├─ 成功/已完成 → 绿色卡片
  ├─ 失败/异常   → 红色卡片
  ├─ 规则/配置   → 紫色卡片
  └─ 帮助/说明   → 蓝色卡片
       │
       ▼
飞书 interactive 消息（标题 + 正文 + 工具标识）
```

## 5. 等待签核流程

```
A 打开等待设置卡片，选择 B、C（仅已登录用户）
  │
  ├─ 检查: B/C 是否直接或间接等待 A？ → 是 → 拒绝（闭环）
  └─ 通过 → 保存多人 ANY 等待，不选择签核/拒签动作

每次 A 的定时任务:
  │
  ▼
check_wait_for(A)
  ├─ 所有人都没有新完成记录？ → 不触发
  └─ B 或 C 任意一人有新完成记录 → 30-60s 随机延时
            → 重新获取最新数据
            → 按 A 当前签核/拒签规则运行一轮
            → 未命中项目保持待手动
            → mark_wait_checked(A)
            → 清除本次等待设置
```

## 6. 异常处理

```
定时任务/签核操作异常
  │
  ▼
┌──────────────────────────┐
│ 捕获异常并生成异常签名      │
│ 首次出现 → 群内 @用户+原因  │
│ 相同异常持续 → 不重复提醒   │
│ 后续成功 → 清除异常状态     │
└──────────────────────────┘
```

## 7. 数据流

```
feishu.json ──→ 飞书 API 配置
config.json ──→ GSC 平台 URL/SSL
sign_events.json ←── 签核事件记录（等待检测用）
data/stats.db ←── 平台复查成功记录（含 open_id、来源、规则、原因、通知状态）

users/ou_xxx/
  auth.json ←── 登录时写入
  rules.json ←── 签核、拒签、通知规则
  groups.json ←── 多个用户组 + 多个内容组
  settings.json ←── 设时间/暂停/多人等待（ANY）

旧版 whitelist.txt / name_blacklist.txt / content_whitelist.txt
  └─ 兼容映射 → 默认用户组 / 限制用户组 / 默认内容组
       └─ 改名或删除 → groups.json 记录 legacy_migrations
            └─ 后续读取与规则执行均不再生成该默认组
```

## 8. 群通知决策

```text
平台复查成功
  ├─ 手动明确 发群/不发群？ → 使用手动值
  ├─ 命中 notification_rules？ → 使用规则 notify
  ├─ 动作规则含 group_notify？ → 使用动作规则值
  └─ 都未命中 → default_group_notify（默认 false）

允许发送时：签核绿色卡片 / 拒签红色卡片 + 拒签原因
```

## 9. 个人统计网页

```text
飞书「统计」卡片 → /stats → 飞书 OAuth → 获得当前 open_id
  → 服务端固定 WHERE open_id = 当前用户
  → 默认语言读取 settings.json.ui_language
       ├─ 最近飞书对话为全繁体 → 繁體
       └─ 最近对话为简体/混用 → 简体
  → 顶部简体/繁體按钮（CSRF 校验后保存个人设置）
  → 统计筛选/统计图/明细
  → 规则编辑（字段联动条件与组下拉）
  → 用户组/内容组配置
  → 设置（含多人等待）
  → 翻译仅作用于显示，不改表单值/规则原文/URL/脚本
  → 导出 Excel（沿用相同筛选和 open_id）
```
