# 凭证、密钥、备份恢复与离职清理

本手册适用于部署根目录（其中包含 `auto-sign/`、`users/`、`data/` 和
`feishu.json`）。签核、拒签不会由以下安全管理命令触发。

## 1. 主密钥

主密钥只放在操作系统密钥服务或项目目录外的权限受限文件中，不进入 Git、发布包、
普通备份或日志。

```bash
python3 auto-sign/qh.py security init-key --output /etc/qh/qh-master.key
chmod 600 /etc/qh/qh-master.key
cat >/etc/qh/qh.env <<'EOF'
export QH_MASTER_KEY_FILE=/etc/qh/qh-master.key
EOF
chmod 600 /etc/qh/qh.env
```

生产服务、计划任务和人工维护终端必须使用同一受控密钥来源。密钥文件应由两名授权
管理员分别保管恢复权限；轮换前先完成加密备份和恢复演练。

`run-server.sh` 和 `run-scheduler.sh` 默认读取 `/etc/qh/qh.env`，因此宝塔启动
命令和计划任务不需要重复写主密钥变量。密钥管理平台直接注入
`QH_MASTER_KEY`/`QH_MASTER_KEY_FILE` 时也继续受支持；可用 `QH_ENV_FILE`
指定其他仓库外环境文件。环境文件不存在且没有外部注入主密钥时，两个脚本都会
明确报错并终止。

环境文件只保存密钥文件路径，不保存到项目目录、Git、发布包或普通备份。不得重新
生成密钥来替换正在使用的密钥；新密钥无法解密现有 `auth.enc` 和 `secrets.enc`。

## 2. 首次迁移

先停止回调服务和定时任务，备份当前运行目录，然后执行：

```bash
cd /www/wwwroot/lfaf.eu.org/qh
source /etc/qh/qh.env
python3 auto-sign/qh.py security migrate --root "$PWD"
```

命令会把 `feishu.json` 的 `webhook_url`、`app_secret`、
`verification_token`、`dashboard_secret`、`ai_key` 写入 `secrets.enc`，
并把 `users/*/auth.json` 和根目录 `auth.json` 迁移为 `auth.enc`。成功后明文
文件会被删除。主密钥缺失或密文校验失败时，系统拒绝读取凭证。

也可不用 `secrets.enc`，直接由密钥管理平台注入以下环境变量；环境变量优先级最高：

| 配置 | 环境变量 |
|---|---|
| webhook_url | `QH_WEBHOOK_URL` |
| app_secret | `QH_FEISHU_APP_SECRET` |
| verification_token | `QH_FEISHU_VERIFICATION_TOKEN` |
| dashboard_secret | `QH_DASHBOARD_SECRET` |
| ai_key | `QH_AI_KEY` |

## 3. 加密备份

备份口令必须从独立密码库取得，不得与主密钥相同。自动任务通过
`QH_BACKUP_PASSPHRASE` 注入；交互运行时命令会隐藏输入并要求复核。

```bash
export QH_BACKUP_PASSPHRASE='从密码库临时注入'
python3 auto-sign/qh.py security backup \
  --root /www/wwwroot/lfaf.eu.org/qh \
  --output /secure-backup/qh-$(date +%F).qhb
```

备份采用 Scrypt 派生密钥和 AES-256-GCM 认证加密，内部清单记录每个文件的大小与
SHA-256。备份不包含主密钥。建议每日备份、至少保留 30 天，并复制到与生产主机隔离
且有不可变保留策略的存储。

## 4. 每月恢复演练

```bash
python3 auto-sign/qh.py security restore-drill \
  --backup /secure-backup/qh-2026-07-29.qhb
```

演练会在临时目录中完成解密、路径安全检查、恢复和逐文件哈希复核，结束后删除临时
副本，不覆盖生产数据。将日期、备份编号、执行人和结果登记到运维工单。

需要人工检查内容时，只能恢复到不存在或为空的暂存目录，并精确重复其绝对路径：

```bash
python3 auto-sign/qh.py security restore \
  --backup /secure-backup/qh-2026-07-29.qhb \
  --target /srv/qh-restore-drill \
  --confirm-target /srv/qh-restore-drill
```

暂存验证通过后，生产恢复应走变更审批、停服务、生产目录另行留档、切换目录和健康
检查流程；本工具不会直接覆盖生产目录。

## 5. 离职账号清理

先从飞书管理员确认离职人员的准确 `open_id`，撤销其飞书应用访问权限，再执行：

```bash
python3 auto-sign/qh.py security offboard \
  --root /www/wwwroot/lfaf.eu.org/qh \
  --open-id ou_xxx \
  --backup /secure-backup/offboard-ou_xxx-2026-07-29.qhb \
  --confirm-open-id ou_xxx
```

命令先生成只含该用户目录和个人统计导出的加密留档；留档成功后才删除用户目录、
`stats.db` 中该 `open_id` 的记录，并清除其他用户设置中对该账号的等待引用。任何
确认不一致、备份失败或路径越界都会终止，且不会删除数据。

建议人事离职工单在账号停用后 24 小时内完成此步骤，并由另一名管理员复核加密留档
可通过 `restore-drill`。
