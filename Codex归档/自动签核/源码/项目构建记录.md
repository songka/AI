# 签核自动工具箱 — 项目构建全记录

## 项目起源

用户已有基础自动签核脚本 `auto_sign.py`（HTTP 登录 GSC 签核平台，白名单判断，自动提交）。需要改造成完整的工具链。

---

## 第一阶段：CLI 工具箱

**需求**：登录、查看待签、签核、拒签

**实现**：
- `cli.py` — 7 个子命令（login/list/show/approve/reject/approve-all/reject-all）
- `auto_sign.py` 增加拒签 radio 检测（ASP.NET 同 name 不同 value 的隐藏 radio）
- 支持 `--dry-run` 测试模式
- ID 范围写法 `1-5`

---

## 第二阶段：凭证分离 + 定时离线决策

**需求**：凭证安全、定时抓取生成 Excel、离线决策、多维规则

**实现**：
- `auth.json` 独立存放密码，不在 config.json 中
- 交互式登录（`getpass` 不回显）
- `rules.json` — AND/OR 多维条件规则引擎
- `export_to_excel()` — 生成决策 Excel（下拉验证+规则预填+统计 sheet）
- `process_excel()` — 读取 Excel 批量签核
- `fetch` / `process` / `run` 命令

**规则引擎** (rules.py)：
- 16 个操作符：equals, not_equals, contains, starts_with, starts_with_any, not_starts_with, starts_with_content_wl, has_cn, is_empty, regex, not_regex, in_list, not_in_list, in_whitelist, in_blacklist
- AND/OR 逻辑组合
- `zhconv` 简体字检测（繁简共用字不算）

---

## 第三阶段：飞书对接

**需求**：飞书群通知、私聊命令、@触发

**实现**：
- `feishu.py` — Webhook/Bot 双模式、卡片构建器
- `cli_feishu.py` — setup/test/send/lookup 命令
- `callback_server.py` — Flask 服务接收飞书回调
- 群通知卡片（自动签核/拒签结果）
- 私发待手动项目
- `card.action.trigger` 事件订阅

---

## 第四阶段：交互卡片

**需求**：飞书卡片点选签核/拒签

**实现**：
- 按钮式交互卡片 `do_query_card()`
- 选中/取消选中 + 确认执行
- **最终放弃**——飞书卡片按钮回调不稳定，改为文本命令（查询 + 签核 1 3）

---

## 第五阶段：多用户系统

**需求**：每用户独立凭证+规则，群@对应用户执行

**实现**：
- `user_manager.py` — 按 open_id 目录管理
  ```
  users/ou_xxx/
    auth.json       — 签核平台登录凭证
    rules.json      — 个人规则
    settings.json   — 时间窗口、暂停、等待设置
    whitelist.txt   — 个人白名单
  ```
- 登录/登出命令：`账号:xxx 密码:xxx`
- 规则管理卡片：暂停/删除按钮
- 白名单管理：加白名单/删白名单/合并到 rules.json 内联
- AI 加规则：自然语言 → 规则 JSON
- 群 @某人 → 以该用户身份查询

---

## 第六阶段：用户设置

**需求**：每用户可自定义自动签核

**实现**：
- 暂停/启动自动签核
- 自定义时间窗口和间隔：`设时间 08:30 21:30 30`
- 等待签核：`等签核 张三 approve`
  - 30-60s 随机延时
  - 防循环检测（A 等 B → B 等 A 拒绝）
  - 需实际签核记录才触发
- `sign_events.json` 事件日志
- 测试自动签核（不实际提交）
- 定时任务改为每分钟遍历所有用户

---

## 第七阶段：外部 AI

**需求**：大模型解析自然语言

**实现**：
- `ai_rule.py` — OpenAI 兼容 API
- 配置 `ai_endpoint` / `ai_key` / `ai_model` 到 feishu.json
- `ai-setup` 命令交互式配置
- 先试外部 AI → 回退内置模式匹配
- 通用 AI 对话：未匹配命令自动送 AI 处理
- AI 可执行 DO:query / DO:approve / DO:reject 等命令

**遇到的问题**：
- DeepSeek/自定义 API 连接超时 → 需服务端修复或换用官方 API
- 内置模式匹配覆盖常见自然语言

---

## 部署历程

### 服务器：RackNerd VPS + 宝塔面板

1. Python 3.9.7 + Gunicorn + Flask
2. 域名 qh.lfaf.eu.org，SSL 用 *.lfaf.eu.org 通配符证书
3. 端口冲突 → 7000 端口 + Nginx 反代失败 → 宝塔 Python 项目自动管理
4. Cloudflare 拦截 POST body → `request.get_json(force=True)` 强制解析
5. Python 3.6 vs 3.9.7 兼容：`from __future__ import annotations`、编码声明、CRLF 换行
6. 死循环 bug：`save_user_rules` ↔ `ensure_user_dir` 递归 → 修复

---

## 已修复的关键 Bug

| Bug | 修复 |
|-----|------|
| 拒签 radio 找不到 | ASP.NET 同 name 不同 value 自动构造 |
| 简体字检测误判（台、系） | zhconv + 共用字排除 |
| 卡片按钮回调 value 为 str | 改为简单 `action|key` 字符串 |
| save_user_rules 死循环 | 去掉 ensure_user_dir 调用 |
| 群通知显示 "?" | 多层回退获取用户名 |
| requirements.txt 版本不一致 | 统一为最新版 |

## 最终架构

```
┌─────────────────────────────────────────────┐
│              宝塔服务器 qh.lfaf.eu.org        │
│                                             │
│  每分钟 cron → cli_feishu.py send           │
│     → 遍历所有用户 → 各自规则 → 自动签核     │
│                                             │
│  callback_server.py (gunicorn :7000)        │
│     ← 飞书事件回调                           │
│     → 多用户管理 + 规则卡片 + AI 对话        │
│                                             │
│  users/ou_xxx/  每用户独立数据              │
└─────────────────────────────────────────────┘
```
