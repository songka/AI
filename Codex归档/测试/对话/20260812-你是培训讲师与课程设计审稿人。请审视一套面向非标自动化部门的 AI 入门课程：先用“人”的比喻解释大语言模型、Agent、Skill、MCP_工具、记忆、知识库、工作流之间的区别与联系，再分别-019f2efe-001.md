## 助手

下面给你一套可直接拆成多份 PPT 的课程设计。我会按“非标自动化部门真实工作场景”来组织，而不是讲抽象 AI 概念。

**总课程定位**

面向对象：电控、机构、软件、文职、生物管/实验支持等岗位的 AI 入门培训。  
建议总时长：4 到 6 次课，每次 60 到 90 分钟。  
课程主线：先让大家知道 AI 系统里“谁像人、谁像工具、谁像流程、谁像经验”，再让每个岗位知道“我明天能怎么用”。

核心比喻：

- 大语言模型：像一个“懂很多话、会推理但没有真实经历的新人顾问”
- Agent：像一个“带目标、会拆任务、会调用工具的助理”
- Skill：像一份“岗位操作手册/专项能力包”
- MCP/工具：像“助理能拿到的仪器、软件接口、查询系统”
- 记忆：像“助理记住你们部门习惯、术语、偏好”
- 知识库：像“资料室/标准库/项目档案柜”
- 工作流：像“标准作业流程 SOP，把多人多步任务固定下来”

## 1）推荐的多份 PPT 课程结构

**PPT 1：AI 是什么：用“人”的比喻看懂 LLM、Agent、Skill、工具、记忆、知识库、工作流**

建议 18 到 22 页。

1. 封面：非标自动化部门为什么现在要学 AI  
2. 课程地图：从“会聊天”到“会干活”  
3. AI 不是一个东西，而是一套协作系统  
4. 大语言模型：像“语言和推理能力很强的新同事”  
5. LLM 的强项：理解、总结、改写、推理、生成方案  
6. LLM 的弱点：会猜、不知道内部资料、不能天然操作软件  
7. Agent：给模型加上目标、步骤、工具使用能力  
8. Skill：给 Agent 装上岗位技能包  
9. MCP/工具：让 AI 能查文件、跑代码、读表格、调系统  
10. 记忆：让 AI 记住“你是谁、你偏好什么、部门怎么叫东西”  
11. 知识库：让 AI 能查“公司自己的资料”  
12. 工作流：把一次性问答变成稳定流程  
13. 七个概念关系图：人、手册、工具、记忆、档案室、SOP  
14. 部门场景总览：电控、机构、软件、文职、生物管  
15. 小案例：从“帮我写周报”到“自动生成项目复盘”  
16. 小案例：从“查一个物料”到“调用 BOM/ERP/图纸资料”  
17. 课堂练习：判断这些需求该用 LLM、Agent、Skill、工具还是知识库  
18. 总结：AI 能力成熟度五层  
19. 下节预告：Skill 怎么用  
20. 课后作业

练习：

- 给 10 个任务分类：  
  “改写邮件”“查某项目历史问题”“生成 PLC 注释规范”“读取 Excel BOM 检查缺料”“根据标准生成测试用例”“记住老板偏好的汇报格式”等。
- 每组选择一个岗位任务，说明需要 LLM、Agent、Skill、工具、知识库中的哪些能力。

**PPT 2：Skill 入门：把岗位经验做成 AI 可复用的“作业指导书”**

建议 20 到 24 页。

1. 封面：Skill 不是插件，而是“可复用的岗位方法”  
2. 回顾：模型会说话，Skill 让它按专业方法干活  
3. Skill 的比喻：老师傅的作业指导书  
4. Skill 适合解决什么：格式固定、判断标准明确、反复出现的任务  
5. Skill 不适合什么：资料缺失、规则天天变、需要最终责任判断的任务  
6. 一个好 Skill 的结构：角色、输入、步骤、判断标准、输出格式  
7. 示例：电控图纸审查 Skill  
8. 示例：机构设计评审 Skill  
9. 示例：软件代码 Review Skill  
10. 示例：文职会议纪要 Skill  
11. 示例：生物管实验记录整理 Skill  
12. Skill 和 Prompt 的区别：一次提醒 vs 可复用能力  
13. Skill 和知识库的区别：会做事的方法 vs 可查询的资料  
14. Skill 编写模板  
15. 反例：过于空泛的 Skill  
16. 正例：可执行的 Skill  
17. 岗位分组练习：把一个日常任务改造成 Skill  
18. 互评标准：是否有输入、步骤、边界、输出  
19. 讲师点评  
20. 落地建议：从 3 个高频低风险任务开始  
21. 课后作业

岗位示例：

- 电控：  
  “根据设备动作流程，检查 I/O 点表是否缺少安全互锁、急停、原点、报警复位。”
- 机构：  
  “根据夹具设计说明，检查定位、限位、防呆、可维护性、易损件更换空间。”
- 软件：  
  “根据接口文档，检查异常处理、日志、重试、权限、配置项。”
- 文职：  
  “把项目会议录音/纪要整理成待办、责任人、截止时间、风险。”
- 生物管：  
  “把实验记录整理成样本编号、试剂批号、操作步骤、异常现象、后续处理。”

练习：

让每组写一个岗位 Skill：

```text
适用场景：
输入材料：
执行步骤：
检查清单：
输出格式：
不能替人决定的事项：
```

**PPT 3：Agent 入门：让 AI 从“回答问题”变成“完成任务”**

建议 20 到 26 页。

1. 封面：Agent 是会拆任务的 AI 助理  
2. LLM 和 Agent 的差别：会答 vs 会办  
3. Agent 的“人设”不是重点，任务闭环才是重点  
4. Agent 的基本构成：目标、计划、工具、记忆、反馈  
5. Agent 工作过程：理解目标、拆解步骤、调用工具、检查结果、汇报  
6. 示例：项目资料整理 Agent  
7. 示例：BOM 初审 Agent  
8. 示例：PLC 报警文本规范化 Agent  
9. 示例：软件缺陷归类 Agent  
10. 示例：实验耗材盘点 Agent  
11. Agent 适合什么任务：多步骤、跨文件、需中间判断  
12. Agent 不适合什么任务：高风险无人审核、规则不清、权限敏感  
13. Agent 的输入要怎么写：目标、范围、资料、验收标准  
14. Agent 的输出要怎么验收：证据、清单、异常项、建议  
15. 人机协作边界：AI 做初稿，人做确认  
16. 课堂案例：让 Agent 生成一次设计评审准备包  
17. 分岗位练习：设计自己的部门 Agent  
18. 失败案例：目标不清导致结果跑偏  
19. 修正方法：加约束、加检查点、加输出格式  
20. Agent 上线前检查清单  
21. 总结

练习：

每组设计一个 Agent 卡片：

```text
Agent 名称：
服务岗位：
主要目标：
需要读取哪些资料：
需要调用哪些工具：
执行步骤：
每一步的人工确认点：
最终交付物：
风险控制：
```

推荐 Agent：

- 电控 Agent：电气设计评审助理  
  输入：电气原理图、I/O 表、动作流程、设备安全要求  
  输出：缺失项、风险项、待确认项、建议修改说明
- 机构 Agent：夹治具方案初审助理  
  输入：3D 截图、设计说明、工艺要求、DFM 清单  
  输出：定位/夹紧/防呆/维护空间问题清单
- 软件 Agent：接口联调准备助理  
  输入：接口文档、日志、异常截图、版本说明  
  输出：联调检查清单、风险接口、测试用例草案
- 文职 Agent：项目周报助理  
  输入：会议纪要、任务清单、问题记录  
  输出：本周进展、延期风险、需领导协调事项
- 生物管 Agent：实验记录整理助理  
  输入：实验表格、照片记录、样本清单  
  输出：记录补全项、异常样本、耗材批次核对表

**PPT 4：MCP/工具入门：让 AI 不只会说，还能查、算、读、连系统**

2. 为什么只靠聊天不够

7. 示例：读取 BOM Excel 并检查料号格式

## 3）课堂主线提示

建议讲师始终围绕这条线讲：

“一个聪明新人进部门，怎么从会聊天，变成能帮忙干活？”

第一步：他会说话、会理解，这就是大语言模型。  
第二步：给他目标，让他拆任务，这就是 Agent。  
第三步：教他岗位方法，这就是 Skill。  
第四步：给他电脑、Excel、ERP、图纸库，这就是 MCP/工具。  
第五步：让他记住你的习惯，这就是记忆。  
第六步：让他查部门资料，这就是知识库。  
第七步：把这些固定成 SOP，这就是工作流。

每讲一个概念，都落回三个问题：

1. 它像部门里的什么角色或资源？  
2. 它能帮我们的哪个岗位省时间或减少错误？  
3. 它不能替人做什么决定？

## 4）必须避免的误解

1. “Agent 就是更高级的聊天机器人”  
   错。Agent 的关键是目标、计划、工具调用和任务闭环。

2. “Skill 就是写一句好 Prompt”  
   错。Skill 是可复用的方法包，包含步骤、标准、边界和输出格式。

3. “MCP 是一个新的 AI 模型”  
   错。MCP 更像连接工具和系统的接口方式。

4. “知识库越多越好”  
   错。过期、矛盾、未审核的资料会让 AI 更容易出错。

5. “记忆可以记所有东西”  
   错。密码、客户敏感信息、未授权资料不应放入记忆。

6. “AI 给出的答案看起来专业，所以就是对的”  
   错。AI 可能编造、误读、遗漏，必须要求来源和证据。

7. “有了 AI 就不用老师傅审核”  
   错。AI 适合初筛、整理、生成草案，关键技术和责任判断仍由人确认。

8. “先做最复杂的自动化场景最有价值”  
   错。第一批应选高频、低风险、规则清楚、资料齐全的任务。

9. “AI 会取代岗位经验”  
   错。岗位经验越清楚，越能沉淀成 Skill 和知识库，AI 才越好用。

10. “工作流就是把几个 Prompt 串起来”  
   错。工作流要包含输入、工具、判断点、人工审核、输出、留痕。

## 5）讲师备注：模拟提问与回答

**问：大语言模型和 Agent 到底差在哪里？**  
答：大语言模型像一个会回答问题的人，你问一句，它答一句。Agent 像一个接到任务的助理，它会先拆步骤，再决定要不要查资料、读文件、调用工具，最后给你一个结果。比如“解释这段报警文本”是模型任务；“读取全部报警表，找出命名不规范项，并生成修改建议”更像 Agent 任务。

**问：Skill 和知识库有什么区别？**  
答：知识库是资料，Skill 是做事方法。比如《电气图纸命名规范》是知识库；“按照命名规范检查图纸并输出问题清单”是 Skill。一个是资料室，一个是老师傅的检查方法。

**问：我们部门是不是应该先建知识库？**  
答：可以，但不要一上来把所有资料都丢进去。建议先选一个高频场景，比如“电控标准”“BOM 料号规范”“项目周报模板”。只放经过确认、版本明确、经常会被问到的资料。

**问：AI 能不能直接帮我审图？**  
答：可以做初审，不能做最终责任判断。它适合检查命名、清单完整性、常见漏项、标准符合性；但涉及安全、结构强度、客户验收承诺、最终技术决策，必须由工程师确认。

**问：电控岗位最适合先用 AI 做什么？**  
答：建议从 I/O 表检查、报警文本规范化、电气图纸审查清单、PLC 注释生成、联调问题整理开始。这些任务重复多、规则相对清楚、人工审核容易。

**问：机构岗位最适合先用 AI 做什么？**  
答：可以先做设计评审清单、DFM 检查、标准件/非标件识别、维护空间检查、夹具防呆建议。AI 不替代受力计算和最终结构判断，但能帮你提前发现漏项。

**问：软件岗位最适合先用 AI 做什么？**  
答：代码 Review 初筛、接口文档整理、测试用例生成、日志归类、异常复现步骤整理都适合。尤其是日志分析和测试用例生成，很容易产生实际收益。

**问：文职岗位是不是只能用 AI 写文章？**  
答：不是。文职场景很适合 AI：会议纪要、任务追踪、周报月报、制度文档整理、项目材料归档、跨部门沟通邮件。关键是让 AI 输出“责任人、截止日期、风险、待确认事项”，而不是只写漂亮文字。

**问：生物管/实验支持怎么用 AI？**  
答：可以用于实验记录整理、样本编号核对、耗材台账检查、试剂批号追踪、SOP 摘要、异常记录归类。注意涉及合规、样本安全、实验结论的内容必须人工确认。

**问：MCP/工具听起来很技术，普通员工需要懂吗？**  
答：不需要懂底层实现，但要懂它的作用。简单说，聊天 AI 只能“凭上下文说”，接工具后才能“读 Excel、查系统、跑脚本、看文件”。普通员工只要知道什么时候需要工具、工具结果怎么验收即可。

**问：AI 为什么会胡说？**  
答：因为它的目标是根据上下文生成最可能的回答，不等于它真的查过公司资料。解决办法是：给它可靠资料、接知识库、要求引用来源、让它列不确定项、关键结果人工审核。

**问：我们如何判断一个场景适不适合第一批落地？**  
答：看四点：是否高频、是否低风险、规则是否清楚、输入资料是否稳定。比如会议纪要、BOM 初筛、报警文本整理适合先做；自动下采购单、自动修改工程图、自动批准验收不适合作为第一批。

**问：如果 AI 答案和老师傅经验冲突怎么办？**  
答：先让 AI 给出依据，看它引用的是哪个规范或哪份资料。然后由工程师判断。如果老师傅经验是正确但没文档化，正好应该沉淀成 Skill 或知识库。

**问：怎么防止大家乱用 AI？**  
答：建立三条规则：敏感资料不随便上传；关键决策必须人工确认；AI 输出要留来源和检查记录。培训里也要强调“AI 是助手，不是签字人”。

**问：我们最后应该产出什么，才算培训有效？**  
答：每个岗位至少产出一个 Skill、一个 Agent 设计卡、一份知识库目录、一个可试点工作流。培训结束后两周内选 1 到 2 个真实场景试运行，统计节省时间和问题发现数量。

**建议最终落地包**

培训不要只交 PPT。建议同时交付：

- 一份《AI 概念速查表》
- 一份《岗位 Skill 模板》
- 一份《Agent 设计卡》
- 一份《知识库建设清单》
- 一份《AI 使用风险红线》
- 一份《部门 AI 试点场景评分表》

这样讲完以后，学员不会只觉得“听懂了”，而是能立刻拿一个真实工作开始试。
