## 助手

下面内容可直接放进课件“讲师备注/审课反馈”。

**1）这些工程师最关心的问题**

电控工程师最关心：

- AI 能不能帮我看懂电气图、PLC 程序、报警逻辑、IO 点表，而不是只会聊天。
- Skill、Agent、MCP 到底哪个能接触真实设备、真实文件、真实软件？边界在哪里？
- AI 生成 PLC 代码、伺服参数、节拍逻辑，出错谁负责？怎么验？
- 能否把过去项目的电气标准、命名规范、报警模板、调试经验变成“可复用能力”？
- 记忆会不会把客户机密、设备方案、程序片段泄露出去？
- AI 能不能接入 EPLAN、TIA Portal、三菱 GX Works、数据库、BOM、测试报告？

机构工程师最关心：

- AI 是否能理解机械结构、气缸选型、治具定位、节拍瓶颈，还是只能写文档？
- 它能不能基于过往项目经验提醒干涉风险、维护空间、装配便利性？
- Skill 和记忆能不能沉淀“我们部门的设计规范”，比如安全门、定位销、模组布局、调节机构标准？
- MCP/工具能不能接 CAD、PDM、BOM、标准件库，而不是手动复制粘贴？
- AI 产生的设计建议是否可靠？会不会一本正经地胡说？
- 它能不能帮忙做评审清单、DFMEA、问题复盘、方案对比？

软件工程师最关心：

- Agent 和普通大模型 API 的区别是什么？是不是只是多套了一层 prompt？
- MCP 是不是类似插件、API 网关、函数调用？为什么不直接调接口？
- Skill 是知识包、提示词、脚本，还是工作流？和 Agent 的职责怎么划分？
- 记忆应该存什么，不应该存什么？如何版本管理、权限管理、审计？
- 非标自动化场景里，哪些任务适合自动化，哪些必须人审？
- 多 Agent 协作会不会引入不可控复杂度？怎么调试、回放、验收？

**2）他们可能提出的尖锐/对抗性问题**

电控工程师可能问：

- “AI 写错一行 PLC，设备撞机了，谁背锅？”
- “你说 Agent 能调工具，那它会不会误操作设备？”
- “我们的电气图纸、客户程序都涉密，凭什么让 AI 记住？”
- “现场调机靠经验和手感，AI 没摸过设备，怎么判断？”
- “它生成的报警说明看着很对，但逻辑错了怎么办？”
- “我现在复制粘贴问 ChatGPT 也能用，为什么还要学 Skill、MCP、Agent？”

机构工程师可能问：

- “AI 连实际装配误差都不知道，怎么给机械方案建议？”
- “它能不能看 3D 模型？不能看模型就别谈设计辅助。”
- “非标项目每个都不一样，所谓知识沉淀是不是没意义？”
- “我们的问题不是不会写报告，是设计时间不够，AI 真能省多少？”
- “如果 AI 建议和老工程师经验冲突，听谁的？”
- “它会不会把一个项目的错误经验记住，后面越帮越错？”

软件工程师可能问：

- “MCP 是不是又一个技术概念包装？和 REST API、插件系统有什么本质区别？”
- “Agent 自主规划听起来很酷，但怎么保证可控、可测试、可复现？”
- “记忆如果会变，系统行为就不稳定，怎么做质量保证？”
- “Skill 如果只是 prompt 模板，那价值是不是被夸大了？”
- “大模型幻觉无法消除，为什么要接入生产流程？”
- “多 Agent 协作是不是把简单问题复杂化？”

**3）讲师应答要点**

回答“AI 写错导致事故谁负责”：

- 要明确：AI 不能直接成为安全责任主体，工程责任仍在人和流程。
- 培训中要强调“AI 参与的是草稿、检查、比对、辅助分析”，不是无审查下发。
- 对电控场景要给出红线：PLC、机器人、伺服、安全回路、互锁逻辑，必须人工评审、仿真、离线验证、现场点检后才能使用。
- 可用比喻：AI 像一个很快的助理工程师，可以帮你整理和提出建议，但不能绕过设计评审和调试规范。

回答“Skill、Agent、MCP、记忆到底怎么分”：

- 大语言模型：大脑，负责理解、生成、推理。
- Skill：标准作业指导书，让 AI 按部门方法做事。
- Agent：会按目标拆任务、调用 Skill 和工具的执行角色。
- MCP/工具：手和眼睛，用来访问文件、系统、数据库、接口、软件。
- 记忆：经验本，保存长期偏好、规范、项目经验，但必须可控、可删、可审。
- 非标自动化例子：  
  “让 AI 帮我做设备方案评审”时，模型负责理解，Skill 提供评审流程，Agent 拆分检查项，MCP 读取 BOM/图纸/历史问题库，记忆提供部门规范和客户偏好。

回答“为什么不用普通 ChatGPT 复制粘贴”：

- 普通聊天适合临时问答。
- Skill 解决“每次按同一套规范做”的问题。
- Agent 解决“一个目标要拆成多步完成”的问题。
- MCP/工具解决“AI 能拿到真实上下文和执行动作”的问题。
- 记忆解决“不要每次重新解释部门习惯”的问题。
- 课上不要贬低普通聊天，而是说明它是入口，后面这些概念是工程化用法。

回答“AI 会不会泄密”：

- 不能只说“不会”，要讲清楚风险控制。
- 明确哪些内容不能进入公共模型：客户图纸、源代码、设备参数、报价、合同、专利方案。
- 介绍企业内控做法：脱敏、权限、私有知识库、日志审计、禁用外传、最小必要输入。
- 记忆不是越多越好，应该只记稳定规则和非敏感偏好，不记客户机密和一次性敏感数据。

回答“AI 不懂现场经验怎么办”：

- 承认 AI 不等于老师傅，也没有真实触觉和现场直觉。
- 它适合做三类事：整理已有经验、补充遗漏检查、快速生成草稿。
- 它不适合替代三类事：安全判断、最终设计签字、现场异常的单点决策。
- 课程中要把 AI 定位成“经验放大器”，不是“经验替代品”。

回答“MCP 和 API/插件有什么区别”：

- 可以说 MCP 本质上是让 AI 和外部工具对接的一种标准化协议。
- 对软件工程师可类比：MCP 像给模型准备的标准工具接口层，让不同工具用一致方式暴露能力。
- 它不神秘，也不是必须替代现有 API；它的价值在于降低 AI 接入多系统时的适配成本。
- 非标场景里可以接：BOM 系统、图纸目录、问题库、测试记录、项目模板、工单系统。

回答“Agent 不可控怎么办”：

- Agent 必须分级授权。
- 低风险：读文件、总结、生成清单，可自动执行。
- 中风险：改文档、生成代码、改参数，必须人工确认。
- 高风险：下发程序、控制设备、改安全逻辑，默认禁止自动执行。
- 要有日志、可回放、工具调用白名单、人工确认点。

**4）建议加入的模拟练习和实际练习**

模拟练习 1：名词角色扮演

- 让学员把一个任务拆成五个角色：大语言模型、Skill、Agent、MCP/工具、记忆。
- 示例任务：“根据客户 URS，生成一份非标设备初步方案评审清单。”
- 讲师引导答案：  
  模型负责理解 URS；Skill 提供评审模板；Agent 拆任务；MCP 读取历史项目和标准件库；记忆提供部门设计偏好。

模拟练习 2：判断该用什么能力

- 给出 8 个场景，让学员判断用普通聊天、Skill、Agent、MCP、记忆中的哪几个。
- 场景示例：
  - “把报警清单翻译成客户能看懂的说明”：普通聊天 + Skill。
  - “读取 BOM，检查气缸品牌是否符合客户 AVL”：MCP + Skill。
  - “每次都按公司格式输出调试日报”：Skill。
  - “跨多个文件找项目延期原因并生成复盘”：Agent + MCP + Skill。
  - “记住某客户不接受某品牌传感器”：记忆，但要注意权限和敏感性。

模拟练习 3：对抗性提问演练

- 分三组扮演电控、机构、软件工程师。
- 每组提出一个最尖锐问题。
- 讲师必须用“三段式”回答：先承认边界，再给控制方法，最后给适合落地的例子。
- 示例：  
  问：“AI 写错程序撞机怎么办？”  
  答：“不能让 AI 直接下发程序；AI 只能生成草稿和检查建议；落地时用于生成互锁检查清单、注释、报警说明，再由工程师评审和仿真。”

实际练习 1：制作一个部门 Skill 草稿

- 主题：“非标自动化项目方案评审 Skill”。
- 学员输入部门常用检查项：
  - 安全防护
  - 节拍估算
  - 上下料方式
  - 维护空间
  - 电气元件品牌
  - IO 点位预留
  - 报警与追溯
- 输出要求：让 AI 固定按“风险点、检查方法、需要资料、责任专业”四列输出。

实际练习 2：把历史问题变成记忆规则

- 给学员 5 条历史问题：
  - 气缸调节空间不足
  - 安全门开关位置不便维护
  - IO 点未预留
  - 客户禁用某品牌
  - 设备节拍计算未考虑扫码时间
- 让学员判断哪些适合进入记忆，哪些应进入 Skill，哪些应留在项目资料库。
- 讲师参考答案：  
  稳定规范进 Skill；长期偏好可进记忆；项目敏感数据进受控资料库，不随便进记忆。

实际练习 3：设计一个 MCP 工具清单

- 让学员为“AI 项目助理”列出可以连接的工具。
- 电控方向：
  - IO 表读取工具
  - 报警清单读取工具
  - PLC 代码只读检索工具
  - 电气标准库查询工具
- 机构方向：
  - BOM 查询工具
  - 标准件库查询工具
  - 历史问题库查询工具
  - 图纸目录检索工具
- 软件方向：
  - Git 仓库查询工具
  - 接口文档查询工具
  - 测试报告读取工具
  - 缺陷单查询工具
- 强调第一阶段建议只读，不直接改生产系统。

实际练习 4：Agent 流程设计

- 任务：“生成某设备项目的设计评审准备包。”
- 让学员设计 Agent 步骤：
  1. 读取客户需求和设备方案。
  2. 提取关键约束：节拍、空间、品牌、安全、追溯。
  3. 调用部门评审 Skill 生成检查清单。
  4. 查询历史问题库找相似风险。
  5. 输出评审问题、责任人、需补充资料。
  6. 标记必须人工确认的项目。
- 讲师重点：Agent 的价值不是“自动替人决定”，而是“把评审前的资料准备完整”。

实际练习 5：红线分类练习

- 给出动作列表，让学员分为“可自动”“需确认”“禁止自动”。
- 可自动：
  - 总结会议纪要
  - 生成调试日报草稿
  - 检查 BOM 字段缺失
  - 生成评审清单
- 需确认：
  - 修改 PLC 注释
  - 生成测试用例
  - 修改项目文档
  - 输出报价说明
- 禁止自动：
  - 下发 PLC 程序
  - 修改安全参数
  - 控制设备动作
  - 删除项目资料
  - 将客户资料上传外部系统

建议讲师在课件里反复使用同一个非标自动化案例贯穿全课：  
“客户提出一台带视觉检测、扫码追溯、自动上下料的装配设备。AI 如何从需求理解、方案评审、BOM 检查、风险复盘、调试文档生成中分别使用 Skill、Agent、MCP、记忆和大语言模型。”这样初学者不会被名词淹没。
