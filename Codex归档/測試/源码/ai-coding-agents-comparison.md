# 多 Agent AI Coding 工具評估系統

## 目的

以多個專責 Agent 分別評估 OpenCode、Codex、Claude Code、Cursor、Aider、Cline、Roo Code、GitHub Copilot 等 AI Coding Agent，最後由總結 Agent 統一整理優缺點、使用後果、風險和適用場景。

## Agent 分工

### 1. 功能與工作流程 Agent

分析：檔案讀寫、終端機指令、測試、除錯、Git 整合、多檔案修改、長任務能力。

輸出：各工具功能評分（1–5）及具體證據。

### 2. 程式碼品質 Agent

分析：生成程式碼的正確性、可維護性、重構能力、測試覆蓋率和大型專案理解能力。

輸出：品質優點、常見錯誤、需要人工審查的地方。

### 3. 效率與生產力 Agent

分析：安裝速度、學習成本、日常開發速度、批量任務能力和互動體驗。

輸出：適合初學者、個人開發者及團隊的效率評估。

### 4. 成本與模型 Agent

分析：訂閱、API、免費額度、模型選擇、Token 消耗和長期使用成本。

輸出：低、中、高成本分類，並說明成本變化的後果。

### 5. 安全與私隱 Agent

分析：程式碼是否離開本機、指令執行權限、祕密資料外洩、供應鏈風險和權限控制。

輸出：低、中、高風險，以及降低風險的建議。

### 6. 開源與可控性 Agent

分析：是否開源、能否自選模型、可否本地部署、插件及設定自由度、供應商鎖定程度。

輸出：自由度評分及長期維護後果。

### 7. 團隊與企業 Agent

分析：協作、權限、審計、政策管理、CI/CD 整合、合規和支援服務。

輸出：個人、小型團隊、企業的適用程度。

### 8. 反方審查 Agent

挑戰其他 Agent 的結論，檢查：

- 是否把宣傳內容當成事實
- 是否忽略模型版本和方案差異
- 是否只比較功能而忽略使用後果
- 是否存在過度概括或未提供證據的評分

### 9. 總結 Agent

收集所有 Agent 的結果，處理衝突，列出證據和信心程度，最後產生比較表及推薦方案。若資料不足，必須標示「待驗證」，不可自行當成確定事實。

## 統一評分標準

| 分數 | 意義 |
|---|---|
| 1 | 很弱或限制明顯 |
| 2 | 基本可用，但缺點較多 |
| 3 | 中等，適合一般用途 |
| 4 | 良好，適合大部分專案 |
| 5 | 卓越，具明顯優勢 |

## 總結 Agent 的輸出要求

1. 先列明測試環境、模型版本、方案和日期。
2. 分開「已驗證事實」「Agent 推論」和「不確定事項」。
3. 對每項推薦說明至少一個優點和一個代價。
4. 最後輸出：整體排名、不同情境推薦、風險清單及匯總表格。
5. 不以單一總分取代分析；若兩個工具適合不同情境，必須並列推薦。

## 建議討論流程

`資料收集 → 專責 Agent 平行分析 → 反方審查 → 總結 Agent 整合 → 人工確認 → 匯總表格`
