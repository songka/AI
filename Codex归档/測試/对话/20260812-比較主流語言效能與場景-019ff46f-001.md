## 助手

- Python
  - 效能：執行速度較慢，CPython 受 GIL 影響；可透過 NumPy、Cython、原生擴充改善。
  - 資源：記憶體與啟動成本中高。
  - 適用：資料科學、AI、腳本、自動化、Web 後端、快速原型。
  - 缺點：高併發 CPU-bound、低延遲系統不理想。

- JavaScript／TypeScript
  - 效能：V8 等 JIT 引擎使 I/O 與一般服務效能良好；CPU-heavy 仍弱於編譯型語言。
  - 資源：Node.js 單程序模型效率佳，但執行時與依賴可能增加記憶體。
  - 適用：Web 前後端、即時服務、API、跨平台工具。
  - 缺點：型別與執行時錯誤需靠 TypeScript、測試及規範管理。

- Java
  - 效能：JIT 預熱後效能高且穩定，適合長時間運行服務。
  - 資源：JVM 啟動時間與記憶體使用較高。
  - 適用：企業後端、大型系統、Android、分散式服務。
  - 缺點：部署較重；短生命週期 CLI 或極低延遲場景成本較高。

- C／C++
  - 效能：接近硬體，延遲低、吞吐量高；C++ 可提供更高階抽象。
  - 資源：可精細控制記憶體與執行緒，效率最佳。
  - 適用：作業系統、嵌入式、遊戲引擎、交易系統、高效能函式庫。
  - 缺點：開發與維護複雜；記憶體錯誤、未定義行為及安全風險較高。

- Go
  - 效能：編譯型語言，效能佳；GC 與執行時使極低延遲不如 C/C++/Rust。
  - 資源：編譯產物與記憶體用量中等，啟動快；併發模型簡潔。
  - 適用：雲端服務、微服務、網路工具、DevOps、CLI。
  - 缺點：泛型與抽象能力相對簡單；GC 不適合部分硬即時需求。

- Rust
  - 效能：接近 C/C++，無 GC，適合高吞吐與低延遲。
  - 資源：記憶體效率高，編譯時間與學習成本較高。
  - 適用：系統軟體、嵌入式、瀏覽器元件、WebAssembly、安全關鍵服務。
  - 缺點：所有權與生命週期學習曲線陡，開發初期速度可能較慢。

- SQL
  - 效能：查詢效能高度依賴索引、執行計畫、資料模型與資料庫引擎。
  - 資源：適合讓資料庫就地處理資料，減少網路傳輸；複雜查詢可能消耗大量 CPU／記憶體。
  - 適用：資料篩選、聚合、交易、報表、資料分析。
  - 缺點：不適合一般業務流程、複雜演算法或高頻逐筆處理；需注意鎖與查詢退化。

- Shell
  - 效能：單純命令與管線方便，但程序建立、文字解析及跨程序溝通成本高。
  - 資源：短腳本資源需求低；大量迴圈或大型資料處理效率差。
  - 適用：系統管理、部署、自動化、檔案與程序編排。
  - 缺點：錯誤處理、可攜性、型別與安全性較弱；不適合大型應用或複雜邏輯。

整體選擇：

- 最高效能與資源控制：C／C++、Rust
- 服務開發與併發生產力：Go、Java、TypeScript
- 快速開發與資料／AI：Python
- 資料庫內資料處理：SQL
- 系統編排與自動化：Shell
