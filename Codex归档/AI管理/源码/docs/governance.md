# 角色与发布治理

| 角色 | 权限 |
|---|---|
| 使用者 | 查询、安装、激活、自动草稿备份、提交候选 |
| 审核者 | 使用者权限 + 审核/驳回；不能发布 |
| 发布者 | 使用者权限 + 发布已审核候选、镜像 |
| 管理员 | 全部权限 + 分配账户角色、恢复与审计 |

自动草稿 Git 双备份对所有已登录用户生效，不属于角色授权动作。正式提交仍需
`candidate.submit`，审核和发布严格分离。

每个发布候选必须包含中文更新说明。打包器优先根据相对上次打包的新增、更新、移除
文件自动生成中文草稿并展示；信息不足时请用户输入。不得虚构测试结果、兼容性或业务
收益。提交端和发布端都拒绝空说明。

发布内容不可原地覆盖；任何内容变化都使用新的 SemVer。依赖必须显式声明，审核者
检查依赖存在性、版本范围、循环、制品摘要、试点和回滚。
