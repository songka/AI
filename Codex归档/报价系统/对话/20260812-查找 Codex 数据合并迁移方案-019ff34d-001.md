## 首选：Codex Migrate

[ChenglongLi777/codex-migrate](https://github.com/ChenglongLi777/codex-migrate)

它正是为“将一台电脑的 Codex 对话合并到另一台已有数据的电脑”设计的，支持 Windows GUI 和命令行。

主要能力：

- 将旧电脑的 `.codex` 数据导出成完整备份。
- 把选定的项目和对话合并到目标电脑现有 Codex 环境，不是覆盖整个目录。
- 同时处理普通对话和已归档对话。
- 可把旧电脑项目路径映射到新电脑路径。
- 导入前预览合并方案。
- 写入前自动创建回滚快照，失败时自动恢复。
- 遇到相同 UUID 时会比较内容：
  - 内容相同：跳过并刷新索引。
  - 一份是另一份的完整前缀：保留较长版本。
  - 内容发生分叉：停止并报告冲突，不会偷偷覆盖。
- 支持把对话导出成包含图片和工具截图的独立 HTML。

项目目前约 45 Stars、15 次提交，MIT 协议，有测试、中文 README 和 Windows 可执行程序。它是第三方社区项目，不是 OpenAI 官方工具。[功能与合并规则](https://github.com/ChenglongLi777/codex-migrate#merge-rules)

## 推荐迁移方法

### 1. 先迁移项目文件

Codex Migrate 迁移的是 Codex 的项目记录和对话，不负责复制你的实际项目目录。

项目代码建议这样转移：

- 已经放在 GitHub/GitLab 的：在新电脑重新 `git clone`。
- 没有放进 Git 的文件：使用移动硬盘或局域网复制。
- 尽量在新电脑上建立统一路径，例如：

```text
旧电脑：C:\Users\Alice\Documents\Projects
新电脑：D:\Projects
```

之后可以一次建立父目录映射：

```text
C:\Users\Alice\Documents\Projects → D:\Projects
```

### 2. 在旧电脑导出

1. 完全退出 Codex Desktop，包括托盘和相关 CLI 进程。
2. 从项目的 [Releases 页面](https://github.com/ChenglongLi777/codex-migrate/releases)下载 Windows ZIP。
3. 校验发布包的 checksum。
4. 解压运行 `Codex Migrate.exe`。
5. 选择旧电脑的：

```text
C:\Users\你的用户名\.codex
```

6. 导出到移动硬盘或加密目录。

工具会创建：

```text
Codex_backup\
```

备份中包含对话、SQLite 数据库、配置、技能和插件等，但会主动排除根目录的 `auth.json`。备份仍然包含聊天内容、命令、截图、本机路径等敏感信息，应当加密传输，不要上传到公开网盘或 GitHub。[备份内容与隐私说明](https://github.com/ChenglongLi777/codex-migrate#backup-contents)

### 3. 在新电脑合并

1. 先完整退出新电脑的 Codex。
2. 单独备份新电脑当前的：

```text
C:\Users\你的用户名\.codex
```

3. 启动 Codex Migrate，选择旧电脑的 `Codex_backup`。
4. 选择需要导入的项目和对话。
5. 设置旧路径到新路径的映射；如果项目暂时还没复制，可以选择仅恢复历史。
6. 先执行 Preview/Dry Run。
7. 确认没有无法解决的 UUID 冲突后再执行导入。
8. 导入完成后重新启动 Codex，检查：
   - 原来新电脑的对话仍然存在。
   - 旧电脑的对话已经出现。
   - 各对话关联到正确项目路径。
   - 随机打开几条长对话测试是否能继续发送消息。

项目提供的标准操作流程也明确要求：退出 Codex、选择会话、映射目录、预览合并、确认导入。[官方使用流程](https://github.com/ChenglongLi777/codex-migrate#typical-gui-workflow)

## 不建议直接复制覆盖 `.codex`

不要直接用旧电脑的整个 `.codex` 覆盖新电脑的 `.codex`，因为里面不只是对话文件，还包括：

- `sessions` 和 `archived_sessions`
- `session_index.jsonl`
- `state_5.sqlite` 及其 WAL/SHM 文件
- `.codex-global-state.json`
- 项目路径、沙箱权限及项目排序信息

直接覆盖会丢掉新电脑已有对话；手工拼文件又可能导致 JSONL、SQLite 和项目索引不一致。OpenAI 官方仓库已经有多起“会话文件仍在，但因为 SQLite、索引或路径不一致而在桌面版消失”的报告，例如[项目路径不匹配问题](https://github.com/openai/codex/issues/24364)和[本地会话存在但侧栏不显示](https://github.com/openai/codex/issues/25463)。

另外，最好让两台电脑的 Codex Desktop 版本尽量一致，再执行迁移。Codex 的内部存储结构并不是稳定的公开接口，Codex Migrate 自己也明确提示未来版本可能需要兼容性更新。

## 其他找到的工具

- [codlogs](https://github.com/tobitege/codlogs)：适合搜索、浏览、导出和脱敏本地对话，偏只读备份，不适合两台电脑之间完整合并。
- [codex-export](https://github.com/ezyyeah/codex-export)：可批量导出 Markdown、HTML、JSON、CSV，但不能恢复进 Codex Desktop。
- [codex-project-path-migrator](https://github.com/pacolaf/codex-project-path-migrator)：专门修复 Windows 上移动/重命名项目后的路径，安全措施比较完善，但不是跨电脑会话合并工具。

结论：你的场景优先使用 **Codex Migrate**；项目代码通过 Git 或文件复制转移，对话通过它的“备份 → 路径映射 → 预览 → 合并导入”流程处理。保留两台电脑的完整原始备份，确认迁移成功一段时间后再清理。

## 助手

那就使用一条父目录映射即可：

```text
旧路径：C:\Users\lfaf-test\Documents
新路径：D:\codex
```

映射后的效果例如：

```text
C:\Users\lfaf-test\Documents\报价系统
→
D:\codex\报价系统
```

迁移顺序：

1. 将旧电脑 `Documents` 下的实际项目复制或克隆到新电脑的 `D:\codex`，保持项目子目录名称不变。
2. 完全退出新旧电脑上的 Codex Desktop。
3. 在旧电脑用 Codex Migrate 导出 `.codex`。
4. 在新电脑打开 Codex Migrate，选择备份并导入。
5. 在“父目录映射／Parent-directory mapping”中填写：

```text
C:\Users\lfaf-test\Documents=D:\codex
```

6. 先执行 Preview/Dry Run，确认所有项目都变成类似：

```text
C:\Users\lfaf-test\Documents\项目名
→
D:\codex\项目名
```

7. 确保 `D:\codex\项目名` 已经真实存在，再执行正式合并。

命令行形式大致是：

```powershell
codex-migrate import "E:\Codex_backup" --dry-run `
  --map "C:\Users\lfaf-test\Documents=D:\codex"
```

预览正确后去掉 `--dry-run`：

```powershell
codex-migrate import "E:\Codex_backup" `
  --map "C:\Users\lfaf-test\Documents=D:\codex"
```

其中 `E:\Codex_backup` 替换成实际备份路径。

注意：如果 `Documents` 下还有非项目目录，建议在 Codex Migrate 中只勾选需要迁移的项目和对话，不要无选择地全部导入。新电脑原有项目如果也准备统一搬到 `D:\codex`，应先处理它们自己的路径变更，再导入旧电脑的数据。
