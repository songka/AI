## 1. 开场与自动发现

收到文件夹或文件时先只读检查，再询问选择。自动发现：

- `SKILL.md`、`skill.json`、`AGENT.md`、`agent.json`。
- references、scripts、assets 和 agents 目录。
- Python、EXE、CLI、BAT/CMD/PS1、Excel、JSON/YAML、图片和模板。
- manifest 声明、实际文件、步骤、工艺、依赖、命令和 ID 是否一致。

先向用户报告“已发现什么”，不要让用户重复描述目录内容。

## 2. 七个引导阶段

### 阶段 A：目标

一次只问：这次希望得到什么？

1. 只检查并给建议。
2. 修复现有 Skill，保持现有路由。
3. 升级为 V2 三层路由。
4. 拆成更专业的多个 Skill。
5. 根据需求训练一套新 Skill。
6. 新建或改写 Agent。
7. 生成配套的 Skill + Agent 组合。

若现有资源有明显协议错误，推荐 2；若职责跨多个工艺/运行时，推荐 4；只有需求或案例时推荐 5。

### 阶段 B：拆分方式

展示根据证据形成的方案，最多三个：

- 共用 Skill：输入输出、所有者、权限、运行时和失败边界相同。
- 按步骤拆分：不同步骤的输出协议和责任不同。
- 按具体工艺拆分：第 6、7、10、11 步的工艺规则差异明显。
- 混合：步骤 1、2 共用；步骤 3、4、7、9、11 优先内部规则；第 5 按类别；第 6、7、10、11 可按工艺。

默认推荐最少但边界清晰的资源数量，不为了“智能”而增加 Agent。

### 阶段 C：执行方式

根据实际文件推荐：

- 提示词 Skill：需要语义理解且已有程序 AI。
- 内部规则：确定性解析、查表、算术、格式检查。
- Python：本地存在 Python 且任务适合脚本。
- EXE/CLI/批处理：工具可再分发、支持非交互运行并有明确退出码。
- Excel 命令：分别声明读取、写入、修改或导出；修改默认另存新文件。
- HTTP：已有稳定服务、认证和超时回退。

只列出检测到或确有需求的选项。

### 阶段 D：Agent

先解释：“Skill 规定做什么和返回什么；Agent 负责需要判断的部分。”然后推荐：

- 无 Agent：纯规则、查表、Excel 或命令任务。
- 复用内置 Agent：角色和协议相同。
- 复用外接 Agent：已有合格专业角色。
- 新建 Agent：工艺知识、输入输出或验收标准确实不同。

若用户选择 Agent，再只问一次操作方式：改写现有、新建、拆分、合并，或随 Skill 一起生成。不要把 `agents/openai.yaml`（Skill 的界面元数据）误认为报价流程的外接 Agent；报价 Agent 必须有 `agent.json` 与 `AGENT.md`。

### 阶段 E：需求满足项目

自动形成检查表并展示：格式、ID、版本、步骤、类别、工艺、输入、输出、证据、Agent 角色、Skill 绑定、运行环境、超时、失败回退、正反例、授权来源、载入发布。每项使用“已满足/部分满足/未满足/待确认”，下一轮只追问最关键的一个缺项。

### 阶段 F：生成范围

一次只问：

- 只生成评估报告。
- 生成到新目录（默认，保留原资源）。
- 原地兼容改写（仅在用户明确授权时）。

生成到新目录时给出准确目标路径和文件清单。

### 阶段 G：载入与发布

生成后说明：

1. 在主程序中选择“载入一组 Skill”或检测单个 Skill。
2. 查看能力和文件结构。
3. 在步骤、类别或具体工艺层选择 Skill 与 Agent。
4. 保存后才发布到公共槽。

未经明确授权，不替用户发布或覆盖公共槽版本。

## 3. 推荐规则

| 证据 | 推荐 |
|---|---|
| 一个文件夹同时做备注、全部工艺、审核和 Excel 修改 | 拆分 |
| 多个资源契约、所有者和规则完全一致 | 合并或共用 |
| 只有 manifest/ID/输出格式不合规 | 标准化 |
| 旧资源仍被路由使用 | 保留兼容，先迁移再弃用 |
| 确定性计算却依赖 AI | 改为内部规则或命令 |
| 不同工艺工时依据明显不同 | 按工艺拆分 Skill/Agent |
| 缺 Python/CLI/Excel 环境 | 保留提示词或内置回退并明确提示 |

## 4. 向导结果卡

每次确认最多显示以下内容：

```text
当前目标：升级并拆分现有 Skill
推荐方案：全局 2 个 + 类别规划 4 个 + 工艺 Skill 若干
推荐原因：工艺工时规则和审核边界不同；Excel 修改有独立副作用
将保留：现有 ID 兼容入口
将新建：列出资源名称
尚待确认：仅列一个当前问题
```

## 5. 典型对话

用户：“帮我看看这个 Skill 能不能用于报价。”

正确引导：先只读盘点，报告发现的步骤、工艺、文件和缺口；然后只问“这次只要评估，还是也生成修复版？”，并推荐评估优先。

用户：“我有铣床和磨床的工时规则，帮我做 Skill。”

正确引导：推荐按工艺拆成两个 Skill，并说明都可接第 6、7、10、11 步；下一轮只问是否共用一个工时 Agent，随后收集正常/反例/歧义/缺失输入样例。

用户：“这里有 Python 和 Excel 模板。”

正确引导：自动检查 Python 脚本入口和工作簿结构；说明 Excel 读取、修改、导出应分别声明；下一轮只问是否允许生成到新目录。

## 6. 错误引导方式

- 错误：第一轮要求用户同时选择模式、目录、11 个步骤、12 个工艺、Agent、运行时和发布位置。
- 错误：没有检查文件就要求用户描述其中内容。
- 错误：只给 `skill.json` 模板，不解释为什么要拆分或如何在程序中选择。
- 错误：用户说“训练”就声称进行了模型微调。
- 错误：发现 EXE 或脚本便直接运行。
