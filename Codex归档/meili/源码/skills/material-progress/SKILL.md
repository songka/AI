# 物料进度

把分散的物料数据整理成可核对的进度、风险和行动项。优先给出业务结论，同时保留计算口径和数据缺口。

## 工作流程

1. 明确统计时点、项目或订单范围、交付节点和期望输出。用户未指定统计时点时，使用当前日期并明确写出日期。
2. 读取全部相关工作表或数据源，识别表头、单位、日期格式、合并单元格、重复表头和空行。处理表格文件时使用对应的电子表格能力。
3. 按 [字段与判定口径](references/field-rules.md) 映射字段。不要仅凭列位置推断含义；对模糊字段保留原始列名并标记假设。
4. 以“项目/订单 + 物料编码 + 批次或交付节点”为优先粒度合并记录。不要把不同批次、不同需求日期或不同单位的数量直接相加。
5. 统一状态、日期和数量，计算完成量、未完成量、进度、预计完成日与风险。数据不足时输出“未知”，不要编造百分比或日期。
6. 检查重复、数量不守恒、完成状态但未完成数量、预计日期早于开始日期等矛盾。将原始记录和推导结果分开。
7. 先输出结论，再输出风险明细和行动清单；按用户明确要求才修改源文件。

## 进度计算

- 有需求数量和已完成数量时：`进度 = min(已完成数量 / 需求数量, 100%)`。
- 只有未完成数量时：`已完成数量 = max(需求数量 - 未完成数量, 0)`，并注明为推导值。
- 只有离散状态时：报告状态分布，不把状态强行换算为虚假百分比。
- 多阶段数据存在时，分别报告采购、生产、发运、到货、检验和入库进度；不要用阶段平均数冒充总体交付进度。
- 需求数量为零、负数或单位不一致时，不计算比例并列入数据问题。
- 汇总比例使用数量加权；若物料单位不可加总，则使用“完成项数/总项数”和分单位数量，不跨单位求和。

## 风险判定

按以下顺序判断，并在报告中说明采用的阈值：

1. **阻塞**：明确标记停产、缺料、质量异常、供应商无法交付或其他阻塞原因。
2. **逾期**：需求/承诺日期早于统计时点且未完成。
3. **数量短缺**：到货、入库或合格数量低于当前应交数量。
4. **临期**：默认在 3 个自然日内到期且未完成；用户给出阈值时以用户口径为准。
5. **日期风险**：预计完成日晚于需求/承诺日期。
6. **数据风险**：关键物料缺少需求日期、数量、状态、责任人，或字段互相矛盾。

同一物料可命中多个风险，但在汇总中按最高严重级别计数一次。不要把“暂无更新”自动解释为正常。

## 输出格式

默认使用以下结构，并根据数据规模压缩：

1. **总体结论**：统计时点、范围、总项数、已完成、进行中、逾期、临期、阻塞和关键数据缺口。
2. **关键风险**：按严重程度、需求日期和影响数量排序，列出物料编码、名称、需求/承诺日期、当前状态、未完成量、责任人、风险原因。
3. **阶段进度**：按采购、生产、发运、到货、检验、入库展示数量或项数口径。
4. **行动清单**：每项写明责任人、动作、截止时间和验证凭据；责任人未知时写“待指定”。
5. **口径与数据问题**：列出推导字段、假设、无法计算项和源数据冲突。

需要生成管理层周报时，限制正文为“一句话结论 + 关键数字 + 前 5 项风险 + 本周行动”；完整明细放在附表。需要更新表格时，新增“标准状态、风险等级、风险原因、建议动作、更新时间”列，避免覆盖原始字段。

## 写入安全

- 默认只读分析，不发送消息、不催办供应商、不修改外部系统。
- 用户要求回写时，先确认目标文件和工作表，尽量写入新列或新工作表，并保留原始值。
- 不静默删除重复记录；标记重复依据并让用户决定保留规则。
- 对外发布前检查敏感字段、供应商信息和个人联系方式。
