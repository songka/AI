# 外购件流水线总控

这是总控技能，负责判断输入、定位 Drive 项目、选择分步技能、约束提问数量和维护项目更新文档。

所有时间统一使用北京时间（Asia/Shanghai，UTC+8），包括项目命名、更新文档、日报、批次记录和邮件内容。

## Drive 项目规则

所有文件必须放在 Google Drive 的 `料号` 父文件夹下面。

- 每个项目都是 `料号/项目名/` 下的一个子文件夹。
- 同一个对话只对应一个项目文件夹；同一对话继续工作时复用原项目。
- 如果用户指定项目，必须在该项目中继续工作，不要新建项目。
- 如果用户要求“列出现有项目”，列出 `料号` 文件夹下已有项目，并显示项目名、最近更新时间和更新文档摘要。
- 如果用户要求“使用某项目”“切换到某项目”“在某项目继续”，先确认该项目在 `料号` 文件夹下存在，再复用该项目。
- 如果用户要求“展示更新文档”“查看项目更新”，读取并展示当前项目的 `项目更新文档.md`。
- 如果用户要求“查看进度”“展示进度文件”，读取并展示当前项目的 `项目进度.md`。

每个项目根目录必须维护两个文档，所有记录时间使用北京时间：

```text
项目更新文档.md
项目进度.md
```

如果 Google Drive 支持 Google Docs，也可以同步创建同名 Google Docs；但至少要保存可读文件。

- `项目更新文档.md`：按时间追加流水记录。
- `项目进度.md`：展示所有目录和关键文件的解释说明，以及当前完成情况。

每完成一个阶段、创建关键文件、遇到阻塞、导出人工复核文件、更新 `assets.json` 或处理邮件提醒时，都要更新这两个文档。

## 必须调用的分步技能

- `external-part-step-00-drive-start`：第 0 步，定位 `料号` 父文件夹，创建/复用项目，归档输入并创建更新文档。
- `external-part-step-01-03-prepare-brand-batch`：第 1-3 步，索引原始表、筛选目标料号、导出品牌待查批次。
- `external-part-step-04-05-brand-research-merge`：第 4-5 步，品牌识别与结果合并。
- `external-part-step-06-08-asset-research-merge`：第 6-8 步，官网图片待查、官网图片研究与结果合并。
- `external-part-step-09-manual-review-export`：第 9 步，循环 3-8 并导出人工复核文件。
- `external-part-step-10-13-assets-finalize-email`：第 10-13 步，导入人工复核、下载图片、更新 `assets.json`、生成日报，并在需要时处理完成邮件提醒。

品牌识别阶段必须使用 `external-part-brand-id`。官网与图片查找阶段必须使用 `external-part-official-image-finder-v3`。

## 自动分流规则

先执行第 0 步，但不要让用户选择执行哪一步。

如果用户上传 `tvs`、`fnd_gfm.tsv`、系统物料表、BOM/物料 XLSX/CSV/TSV：

- 自动执行第 1-9 步。
- 常规情况下只问两个问题：
  1. 如果用户同时上传原始 TSV/物料表和 `assets.json` 两个文件，或当前项目已有可用资产索引，必须询问“更新原资料”还是“跳过原有”。用户明确选择前不得默认跳过、默认更新、筛选或覆盖原资产。
  2. 询问流程全部完成后是否需要邮箱提醒；如果需要，只索取收件者邮箱。
- 不要询问是否执行 1-9，也不要询问下一步应该做什么。
- 用户确认资产处理模式和邮件提醒偏好后，必须自动连续执行到第 9 步并导出人工复核文件；第 1-9 步中间不要反复要求用户确认。

如果用户上传已修订的 `人工复核工作簿.xlsx`：

- 自动执行第 10-13 步。
- 常规情况下只问一个问题：流程完成后是否需要邮箱提醒；如果需要，只索取收件者邮箱。
- 不要询问是否执行 10-13，也不要重复询问资产模式。

如果用户上传旧版 `manual_brand_fix.csv` 和 `manual_asset_fix.csv` 两个人工审核完成文件，也按兼容路径自动执行第 10-13 步；但不要要求用户把 xlsx 手动转换成 CSV。

如果原始物料表和人工审核文件同时出现，才询问用户先执行哪一段。

## 循环与断点续跑

本流程必须支持循环执行和意外打断后继续，且这是可行的。

- 如果 ChatGPT Web 显示 `Usage limits exceeded. Not running this agent.`，视为平台额度中断，不是用户输入错误，也不是流程失败。
- 下次用户说“继续之前的流程”“继续这个项目”“开始”“接着跑”时，必须优先从当前 Drive 项目恢复，不要要求用户重新上传 TSV 或 `assets.json`。
- 恢复时先读取 `料号/{项目名}/00_项目启动/run_config.json`、`项目进度.md`、`项目更新文档.md`、`01_原始表索引/`、`02_目标料号筛选/`、`03_品牌待查/` 中已保存的输入、索引和队列文件。
- 只有项目文件夹中确实缺少原始 TSV/物料表、`assets.json` 处理基准以及可恢复队列时，才说明缺少哪些文件并要求用户补传对应文件。
- 第 1-9 步是机器研究循环：按批次反复执行 3-8，直到所有目标料号完成机器处理并导出第 9 步人工复核文件。
- 用户上传 TSV/系统物料表后，必须处理其中所有满足筛选条件的目标料号；不能只处理部分批次就进入人工复审。只有所有目标料号都完成品牌阶段、官网图片阶段或被归入待人工复核原因后，才能执行第 9 步导出人工复核文件。
- 第 10-13 步是复核入库循环：按人工修订结果反复导入、下载图片、更新资产索引和日报，直到全部完成。
- 每个关键步骤完成后都要更新 `00_项目启动/run_config.json`、`项目更新文档.md` 和 `项目进度.md`。
- 每个批次都必须稳定命名，不覆盖历史批次。
- 意外中断后，智能体必须先读取当前项目的 `项目进度.md`、`项目更新文档.md`、`00_项目启动/run_config.json` 和各步骤目录中的最新文件，再判断从哪个步骤继续。
- 已完成且产物有效的批次不要重跑；只继续未完成、缺失结果或验证失败的部分。
- 如果用户说“继续之前的”“继续这个项目”“恢复流程”“接着跑”，默认执行断点续跑，不要从头开始。

## 项目目录结构

在 `料号/项目名/` 下维护：

```text
项目更新文档.md
项目进度.md
00_项目启动/
01_原始表索引/
02_目标料号筛选/
03_品牌待查/
04_品牌识别/
05_品牌合并/
06_图片待查/
07_官网图片查找/
08_图片合并/
09_人工复核/
10_复核导入/
11_图片下载/
12_资产索引/
13_日报邮件/
```

所有输入、中间文件、复核文件、报告、图片和最终 `assets.json` 都必须保存到当前项目文件夹。不要只在聊天中输出正式结果。

## 邮件提醒规则

邮件提醒只用于两个循环都完成后的结果通知。可以在启动 1-9 或 10-13 时提前询问并记录提醒偏好，但不要在第 9 步单独发送完成邮件。

如果用户需要邮件提醒，只索取收件者邮箱。邮件主题、正文、附件或 Drive 链接清单由智能体自动生成。发送前必须确认收件者、主题、正文和附件/链接清单。没有 Gmail 工具权限时，不要声称已发送，改为生成 `13_日报邮件/completion_email_draft.md`。

如果流程中间出现意外打断、阻塞、校验失败、缺少输入、需要用户人工确认，且 `00_项目启动/run_config.json` 已设置邮箱提醒，也要发送或生成待发送提醒：

- Gmail 可用时，自动生成“需要处理/流程中断”邮件，说明当前项目、当前步骤、阻塞原因、需要用户做什么、Drive 项目链接和 `项目进度.md` 链接。
- Gmail 不可用时，生成 `13_日报邮件/action_required_email_draft.md`。
- 不要在无法继续时静默停止。
- 如果发送动作本身需要用户确认，则先在聊天中展示邮件内容并等待确认；如果平台允许预授权自动提醒，可按用户已设置的邮箱发送。

## 每次回复格式

每次回复末尾必须用中文报告：

```text
当前项目：
当前阶段：
已保存：
下一步：
需要用户确认：
```

## 向用户展示可用提示词

在项目启动、列出项目、展示进度、流程完成或发生阻塞时，向用户展示可用提示词示例，让用户知道可以怎么继续操作。

可用提示词：

```text
列出现有项目
使用/切换到/继续 <项目名>
查看进度
展示更新文档
继续之前的流程
额度中断后继续
上传 TSV 和 assets.json，开始处理
上传审核后的人工复核工作簿.xlsx，继续入库
更新原资料
跳过原有
需要邮箱提醒，收件者是 <邮箱>
不需要邮箱提醒
重新发送完成提醒
生成邮件草稿
```

## 禁止事项

- 不要在 Google Drive 根目录或其他目录乱建项目；所有项目必须在 `料号` 文件夹下。
- 不要跳过第 0 步。
- 不要在常规路径上询问用户要执行哪个步骤。
- 不要伪造已创建、已上传、已下载、已复核、已更新或已发送邮件。
- 设置了邮箱提醒时，不要在阻塞或需要人工确认时静默停止。
- 不要在缺少证据 URL 时把品牌、官网或图片结论写成 `confirmed`。
- 不要把淘宝、天猫、1688 单独作为官方确认依据。
- 不要覆盖历史批次，除非用户明确要求重跑该批次。
- 不要在用户未确认 `assets.json` 处理模式前筛选或覆盖原资产。
- 不要在用户已确认资产处理模式后，于第 1-9 步中间反复停下询问是否继续。
