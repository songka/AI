本机实际情况：

- OpenCode Desktop 版本：`1.18.18`
- 可执行文件：`%LOCALAPPDATA%\Programs\@opencode-aidesktop\OpenCode.exe`
- 主数据目录：`%USERPROFILE%\.local\share\opencode`
- 主数据库：`opencode.db`，同时存在 WAL/SHM
- 数据库包含 `session`、`message`、`part`、`project` 等当前表
- `%APPDATA%\ai.opencode.desktop` 主要是 Electron 状态和 `drafts.sqlite`，不是主会话库

漏检原因：

- Adapter 能检测到 `.local\share\opencode`，但只扫描旧版 JSON/JSONL，完全没有读取 `opencode.db`。
- 可执行文件查找没有覆盖 `@opencode-aidesktop\OpenCode.exe`。
- 因此会出现“已检测 OpenCode，但会话数为 0”。

建议修复顺序：

1. 增加 Desktop EXE 安装检测，但不要把它当作普通 CLI 调用。
2. 若独立 OpenCode CLI 可用，继续优先使用 `session list` 和 `export`。
3. Desktop-only 环境使用 SQLite 只读 fallback：
   - `mode=ro`
   - 让 SQLite 同时读取 WAL，不能只复制主 `.db`
   - 查询 `session`、`message`、`part`
   - 将 `data` JSON 组合成官方 export 结构
4. 启动前检查 `sqlite_master` 和 `PRAGMA table_info`，兼容 Schema 漂移。
5. 缺少关键表时提供明确诊断，绝不触发 migration 或写入。

Desktop 确实运行过本地认证 sidecar API，但密码通过进程 IPC 管理，外部程序不应从日志抓取，因此不能作为稳定集成入口。
