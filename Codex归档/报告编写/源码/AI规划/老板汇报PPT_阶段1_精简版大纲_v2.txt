《内部 AI 框架与五类 Skill 建设规划》
精简版故事线 v2（待确认）

一、关键事实修正

1. Skill Hub 尚未建立，不能在汇报中写成“已上线”或“已有能力”。
2. 当前规划是在 SMB 公共槽集中存放 Skill，使多台个人 PC 上的 opencode / Claude Code 可以共同读取与使用。
3. 公共电脑上的 DeepSeek 继续承担公共模型能力；SMB 公共槽承担第一阶段的 Skill 共享、版本和发布载体。
4. “Skill Hub”可作为后续治理目标，但当前页面统一使用“SMB Skill 公共槽”，避免老板误以为已有完整平台。

二、推荐 SCR

Situation：公司已有个人 AI 编程客户端和公共电脑 DeepSeek，具备内部共享 AI 能力的基础。
Complication：Skill 仍未形成公共、统一、可维护的能力库；各工程领域规则分散，网络下载的通用 Skill 也无法直接满足公司设备和工程规范。
Resolution：第一阶段不建设复杂平台，先用 SMB 公共槽建立简单可用的 Skill 共享框架；围绕 PLC、Robot、PC 程序、视觉程序、办公五大类开发；以网络下载的 PLC Skill 为例，裁剪并改写为台达 AS228T 专精 Skill。

副标题：以 SMB 公共槽共享工程能力，先形成可用闭环，再逐步完善治理

信息密度：低至中。

P3 构建框架
结论标题：先用公共 DeepSeek + SMB Skill 公共槽搭建轻量框架，让个人电脑共享同一套能力
页面内容：
- 个人 PC：opencode / Claude Code，作为工程师使用入口；
- 公共电脑：DeepSeek，作为公共模型服务；
- SMB 公共槽：集中存放经过批准的 Skill、公司规则、模板和示例；
- 多台个人 PC 从 SMB 加载同一版本 Skill；
- 管理员负责发布、版本、备份和回滚；
- 明确标注：Skill Hub 尚未建设，SMB 是第一阶段的共享载体。
视觉：重做 slide-03 的架构图。三台个人 PC → 公共 DeepSeek；三台个人 PC 同时读取 SMB Skill 公共槽；管理员向 SMB 发布 Skill。已建部分用实线，后续治理能力用虚线。
SO WHAT：先低成本解决“大家都能用同一套 Skill”，再考虑平台化。

P4 五大类 Skill
结论标题：首批建设五大类 Skill，覆盖工程开发与日常办公的核心场景
五类：
1. PLC Skill：台达 AS228T，生成全局变量、局部变量和 ST 程序；
2. Robot Skill：那智、Fanuc、汇川牌分别专精；

3. PC 程序 Skill：固化公司标准程序框架、通信、日志、异常和测试规范；
4. 视觉程序 Skill：围绕相机、算法平台和 PLC/PC 接口进行二次开发；
5. 办公类 Skill：报告、表格、PPT、会议纪要和知识检索。
视觉：五条能力泳道或五分支能力树，不做五张大卡片。
SO WHAT：Skill 不是通用问答，而是把公司做法变成可重复调用的能力。

P5 开发与维护方式
结论标题：每类 Skill 都必须有负责人、公司规则、示例和验收标准
页面内容：
- 领域 Owner：决定规则和适用边界；
- Skill 编写人：将规则、模板和流程写入 Skill；
- 验收人：用真实项目检查输出；
- SMB 管理员：负责公共槽发布、版本、权限、备份与回滚；
- 使用者：反馈错误和新场景。
最小交付包：SKILL.md + references + templates/examples + evals。
视觉：简化责任链，不使用大型 RACI 表。
SO WHAT：没有负责人和真实项目验收的 Skill 不进入 SMB 公共槽。

P6 网络 Skill 为什么必须改写
结论标题：网络下载的 PLC Skill 只能作为素材库，不能直接作为公司生产 Skill
证据：
- 现有包共有 111 个文件、110 个 Markdown；
- 覆盖 10 个厂商，但台达目录仅 3 个文件；
- 全文没有 AS228/AS228T 专属内容；
- 台达规则主体偏 DVP；
- 通用 ST 风格文件明确面向三菱 FX3U/GX Works2；
- 包内没有公司地址分配、变量命名和程序框架规则。
视觉：左侧“网络通用包：宽而杂”，右侧“公司专精 Skill：窄而深”，中间显示保留、删除、重写三类动作。
SO WHAT：网络 Skill 可以提供结构和通用模板，但厂商、型号和公司规则必须重新校准。

P7 AS228T 改写目标与下一步
结论标题：将网络 PLC Skill 改写为只服务台达 AS228T 的公司专精 Skill
改写范围：
- 删除其他 9 个厂商及 DVP/三菱相关规则；
- 补充 AS228T、ISPSoft、ST 语法和工程结构；
- 加入公司地址分配、变量命名、程序框架、报警/互锁/复位规则；
- 固定输出三件套：全局变量、局部变量、ST 程序；
- 加入完整性、地址冲突、命名、变量引用、输出单写和回归测试；
- 用真实 AS228T 工程样例验收后发布到 SMB 公共槽。
需要老板支持：指定 PLC Owner 与验收人；提供公司规则、AS228T/ISPSoft 工程样例；批准 SMB 公共槽的权限与版本管理方式。
视觉：网络 Skill → 裁剪/重写 → AS228T 三件套 → 验收 → 发布至 SMB 的单一流水线。
SO WHAT：先把一个 PLC Skill 做深做实，再按相同方法复制到 Robot、PC、视觉和办公类。
