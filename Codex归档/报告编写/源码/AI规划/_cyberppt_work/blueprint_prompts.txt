SLIDE 01
低密度封面。可见主标题「内部 AI 框架与工业 Skill 建设规划」，副标题「从个人工具试用走向可治理、可复用、可验收的工程能力」，小字「老板汇报版｜2026年7月」。构图：左侧约 58% 标题，右侧约 42% 为精致抽象技术主视觉——中央 Skill Hub 能力节点连接 PLC、机器人、PC、视觉与办公终端，层叠半透明蓝灰线路与细线节点，保持大量有意图的象牙白留白。页脚极简。不要出现数据图表和密集卡片。

SLIDE 02
结论标题「当前最需要批准的不是更多 AI 客户端，而是一套统一治理的能力底座」。副标题强调入口与模型已有雏形。版式：左侧 64% 做“已有能力 / 关键缺口”双栏对照，已知用深蓝实线、缺口用铜橙细标；右侧 36% 为三项管理层决策请求的纵向决策栏。底部贯穿 SO WHAT 结论条「模型解决生成能力，Skill 与治理决定工程可用性」。显示已有：个人端、公共 DeepSeek、Skill Hub、五类 Skill；缺口：认证权限、规则版本、质量门、Owner。高密度、非卡片墙。

SLIDE 03
结论标题「个人端—公共模型—Skill Hub 的雏形已经形成，但关键控制面尚未建立」。主视觉占 76%：从左下三个个人 PC（opencode / Claude Code）汇聚到中央公共电脑 DeepSeek，再连接右上 Skill Hub 的架构拓扑；使用流畅但克制的细蓝连接线。右侧窄栏列出六个待确认控制点：认证、权限、版本、日志、发布、回滚，用铜橙虚线锚点标记。底部图例区分“已知事实”和“待建设/待确认”，并有 SO WHAT「不改变个人端，统一控制模型、规则和输出」。避免线条穿过节点和标签。

SLIDE 04
结论标题「目标架构应把模型能力、公司规则和个人入口解耦，Skill Hub 成为唯一受控能力层」。主图为五层横向分层架构：个人客户端、统一接入、模型服务、Skill 编排、规则与模板；左到右或下到上的清晰端到端请求流。Skill 编排层突出 PLC、Robot、PC、Vision、Office 五个能力节点。右侧治理审计栏贯穿全层：身份、权限、版本、审计、发布、回滚。底部 SO WHAT「模型可替换，公司的工程规则必须沉淀在 Skill Hub」。技术感但不是网络安全海报或 UI dashboard。

SLIDE 05
结论标题「五类 Skill 统一纳入 Skill Hub，但采用不同的优先级、风险等级和验收门」。左侧约 60% 为“业务价值 × 可标准化程度”二维矩阵，五个直接标注的 Skill：PLC AS228T、Robot、PC 程序、视觉程序、办公类；P0/P1/P2 用深蓝浓淡和铜橙小标。右侧 40% 为精炼能力表，逐行说明优先级与输出。底部 SO WHAT「同一平台、分域治理、分级上线」。矩阵标签必须横向直接标注，无图例依赖。

SLIDE 06
结论标题「机器人能力应采用共性工程层与品牌专精层，禁止混用指令和坐标语义」。构图为稳定的“共性底座托起三品牌塔”：底部共性工程层含工艺流程、点位坐标、I/O 握手、报警恢复、节拍、安全边界；中上部并列那智、Fanuc、川崎三种品牌模块，每个都有工程结构、品牌指令、坐标系、程序格式的标注；右侧 25% 为统一输出契约：程序骨架、点位清单、I/O 表、恢复逻辑、验收清单。底部铜橙安全边界提示。非三张普通卡片。

SLIDE 07
结论标题「PC 程序 Skill 的价值是让新项目默认落入公司标准框架」。左侧 65% 为分层软件架构剖面，从项目目录、配置、日志、异常处理、设备通信抽象、数据接口到测试发布，形成一个连续的技术框架体；左边小型输入流：业务需求、技术栈、设备接口、部署环境；右侧 35% 为输出物垂直清单：项目骨架、模块清单、接口契约、关键代码、配置样例、测试用例、部署说明。用蓝色主路径强调从需求到可运行骨架，底部质量门和 SO WHAT。

SLIDE 08
结论标题「视觉 Skill 应围绕现有相机与算法平台建立二次开发闭环」。主图为贯穿页面的闭环路径：需求与硬件/SDK → 光学与标定 → 采图与算法 → 结果判定 → PLC/PC 通信 → 异常重试 → 数据追溯回流；使用一条优雅、可追踪的深蓝弧形闭环和工业视觉图标，节点密度高但标签清晰。右侧窄栏列七类输出。底部铜橙风险条「没有真实图像、节拍及误判漏判指标时不承诺效果」，SO WHAT 强调可复现工程闭环。

SLIDE 09
结论标题「办公 Skill 优先解决高频、低风险、可复核的文档工作」。左侧约 62% 为“使用频率 × 风险等级”矩阵，标注报告与制度、表格分析、PPT 汇报、会议纪要与任务、内部知识检索；右侧 38% 为共性模板层和权限边界：公司模板、术语、密级、审批与引用。底部横向输出带显示可编辑 DOCX、XLSX、PPTX、摘要、行动项、引用清单，并突出外发/发送/删除需二次确认。成熟办公治理感，不做软件 UI。

SLIDE 10
结论标题「每个 Skill 必须同时拥有业务 Owner、规则维护人和验收人」。主区 72% 为紧凑 RACI 表，行是平台负责人、PLC Owner、机器人品牌 Owner、PC 程序 Owner、视觉程序 Owner、办公 Owner、验收人、使用者；列是规则编写、样例脱敏、测试、评审、发布、反馈、回滚。用深蓝圆点和字母清晰编码。右侧 28% 为从规则维护到验收签字再到生产发布的责任链及升级路径。底部 SO WHAT「没有 Owner 的 Skill 不进入生产」。表格高密度、行列易读。

SLIDE 11
结论标题「现有 PLC 包素材丰富但目标错位，必须裁剪为 AS228T 单型号专精 Skill」。顶部做五个关键数字但不是 KPI 卡片墙：111 个文件、110 个 Markdown、10 个厂商目录、台达仅 3 个文件、AS228T 专属命中 0，以一条连续证据带呈现。中部左侧为“十厂商宽而浅”扇形/谱系图，右侧为“AS228T 窄而深”纵深能力柱，对比清楚。右侧或下方红橙风险区标出三项冲突：通用十厂商、台达主体偏 DVP、ST 风格面向三菱 FX3U/GX Works2。底部 SO WHAT。

SLIDE 12
结论标题「AS228T Skill 的首要产品是稳定生成可评审的三件套工程包」。主流程占 70%：工艺需求、I/O 表、设备清单、控制模式、公司规则进入六阶段流水线——完整性检查、地址与命名、程序框架选择、生成、静态检查、人工验收；失败通过铜橙回路退回补充或修改。右侧 30% 展开三件套：全局变量表、局部变量表、ST 程序，附假设、风险、测试清单。三件套使用层叠工程文档形态而不是普通卡片。底部 SO WHAT「从回答问题升级为交付可验收工程包」。

SLIDE 13
结论标题「公司规则必须作为独立、可版本化的 reference 进入 Skill」。左侧 45% 为规则优先级金字塔，自上而下：项目专用规则、公司统一规则、AS228T 官方规则、通用 IEC/工程模式；右侧 55% 为清晰的 reference 文件结构树，四类主分支：地址分配、变量命名、程序框架、控制模式与报警互锁复位，每个分支带 Owner、版本、适用范围、正反例四种元数据标记。底部待补资料清单和 SO WHAT「Skill 只执行已批准规则，不替公司发明标准」。

SLIDE 14
结论标题「规则合规、语法可用、逻辑可测和工程师签字必须同时通过」。主视觉为五级质量闸门，左到右：输入完整性、规则静态检查、语法/编译、仿真或离线测试、工程师评审签字；每一门下方分配地址冲突、命名、变量引用、输出单写、状态、报警、复位、异常、编译、回归十个检查点。自动检查用蓝色齿轮，人工验收用轮廓人物/签字图标。失败路径用铜橙箭头回退。右下角准入徽章「全部通过才可生产」。

SLIDE 15
结论标题「先补规则与样例、完成 AS228T 闭环，再按资料成熟度扩展其他 Skill」。五阶段水平路线图占主画面：阶段0 指定 Owner/归集规则样例；阶段1 AS228T MVP/三件套静态检查；阶段2 真实项目回归/生产发布回滚；阶段3 机器人、PC、视觉孵化与办公快速试点；阶段4 指标运营/规则持续迭代。每阶段下方有明确退出标准和依赖标记。用连续深蓝路径连接，阶段门是精致技术里程碑，不是五张卡片。底部 SO WHAT。

SLIDE 16
结论标题「建议今天批准一个平台方向、一个首发 Skill 和一套责任机制」。左侧 62% 为五项管理层决策清单，使用大号 01-05 和勾选框：统一 AI 框架与 Skill Hub、AS228T 作为 P0、五类 Skill 纳入组合、指定各域 Owner 与验收人、同意真实工程环境准入验证。右侧 38% 为批准后的三项立即启动动作：提交公司规则、提供 2-3 个脱敏工程样例、建立第一版测试集；保留 Owner 姓名空位。底部深蓝最终结论条「用一个可验收样板，建立可复制的内部 AI 能力机制」。收束有决策感，不用“谢谢”。
