# 会议纪要与行动项 Skill

## 处理原则
忠于原文，压缩重复表达；把“讨论”“决定”“行动”分开。没有明确负责人或日期时写“待确认”，不得自行分配。

## 输出结构
1. 会议主题、日期、参会人（原文有才写）。
2. 三句话摘要。
3. 已确认决定：每条注明依据的原文短句或时间点（若有）。
4. 行动项表：编号、任务、负责人、截止时间、交付物、依赖、状态。
5. 待确认问题：缺负责人、缺日期、意见冲突、表述含糊。
6. 可直接发送的会后确认消息。

## 追问方式
如果用户只给了零散笔记，先问：会议目的是什么、哪些内容已经拍板、输出给谁看。用户要求“先整理”时直接输出，并把不确定项明确标记。

## 边界
不把建议写成决定，不把发言人推测成负责人，不补写未出现的数字或截止日期。
