# 电气技术报告与培训 PPT

按“选择 → 材料 → 补缺 → 文稿确认 → PPT”的顺序执行。未获得明确确认前，不生成 PPT。

## 1. 建立任务卡

首轮只问以下内容，并尽量合并为一次简短选择：

1. 输出类型：`老板技术报告` 或 `上课教材`。
2. 视觉风格：
   - `公司模板`：使用 [company-template.md](references/company-template.md) 中登记的 PPTX。
   - `商务简洁`：结论优先、正式克制。
   - `工业科技`：深色或蓝灰色、技术感、适合设备与数据。
   - `培训清晰`：浅色、高可读性、步骤和重点突出。
3. 只有选择上课教材时，再问受众：`新员工` 或 `工程师`。
4. 请用户提供材料，可接受文件、文件夹、截图、表格、聊天记录或直接粘贴的要点。

不要在首轮询问页数、章节等次要问题。将已知信息保存在内部任务卡中：`类型｜受众｜风格｜材料｜时间范围｜目标｜限制｜待确认`。后续只更新变化项，不向用户复述整张卡。

## 2. 读取材料

先列出用户明确提供的文件，仅读取与任务相关的内容。优先批量提取文字、表格标题、图片说明和关键数据；不要逐页复述原材料。

- 选择公司模板时，才读取 [company-template.md](references/company-template.md)，检查文件存在后按 `Presentations` 技能的 template-following 流程分析完整模板。
- 制作老板技术报告或周报时，按需读取 [weekly-report-examples.md](references/weekly-report-examples.md)。先根据文件名和当前主题筛选最相关的 1–2 份；只有需要借鉴叙事、栏目、术语或视觉表达时才分析，禁止默认加载全部历史报告。
- 未选择公司模板时，不读取或分析该大文件。
- 材料之间冲突时，指出具体冲突并询问；不可自行编造数值、日期、项目状态或故障原因。
- 缺少非关键细节时采用合理默认值，并在文稿中以“待确认”标记，不为小问题打断流程。

## 3. 只补关键缺口

分析材料后，一次最多问 3 个高价值问题。只询问会改变叙事、结论或准确性的缺口。

老板技术报告优先确认：汇报目标/时间范围、最重要结论、异常与影响、关键数据口径、希望领导知晓或决策的事项。不要强制套用固定周报栏目；依据材料自由组织技术叙事。

上课教材优先确认：课时、已有基础、必须掌握的技能、设备/软件环境、安全边界。若用户未指定章节，使用固定章节：

1. 课程目标与适用对象
2. 基础原理与关键概念
3. 系统/元件/工具认识
4. 标准操作或设计流程
5. 典型案例与故障分析
6. 安全注意事项与常见错误
7. 课堂练习或检查题
8. 总结与课后任务

新员工版侧重术语解释、操作顺序、安全与图片示意；工程师版侧重设计依据、参数、选型、计算、诊断逻辑与边界条件。

### 检查图片与内容缺口

补问完成后、输出逐页文稿前，检查每个核心结论是否有足够证据和合适视觉。重点检查：现场/设备照片、机构或电气结构图、流程截图、趋势数据、参数表、故障现象与整改前后对比。

若缺少会明显影响可信度或可读性的内容，先发送一份简短缺口清单：

```text
建议补充：
1. 第 X 页｜缺少：现场全景照片｜用途：说明设备范围
2. 第 Y 页｜缺少：节拍/良率数据｜用途：支撑改善结论
请选择：A 你补充材料；B 授权我网上找替代素材；C 保留无图/标记待补。
```

一次最多列 5 项，按重要性排序。用户选择 A 时等待其材料；选择 B 时才联网搜索。替代素材必须准确对应通用概念，标明为示意图及来源，不得冒充用户现场、设备实拍、内部数据或实际结果。对于内部项目状态、故障原因、参数和业绩数据，只能由用户补充或标记待补，不能从网上替代。用户选择 C 后继续，并在文稿中标记对应页面。

## 4. 输出非 PPT 文稿供确认

材料足够后，输出紧凑的“逐页文稿”，不要创建 PPTX。格式如下：

```text
建议：N 页｜预计讲解 M 分钟
01 封面：标题｜副标题
02 页面标题：结论句
   - 要点 1
   - 要点 2
   - 视觉：图表/流程/现场照片/无
...
待确认：仅列仍影响成稿的事项
```

老板报告的页面标题优先写成结论句；教材页面标题优先写成学习动作或知识点。每页保留 2–4 个要点，避免写演讲稿。材料中有数据时说明推荐图表及数据字段，不虚构数据。

文稿末尾只问：`请确认文稿，或直接指出要修改的页码和内容。确认后我再生成 PPT。`

收到修改意见时只重发修改页及受影响的目录/总结；用户要求看完整稿时才完整重发。只有用户明确表示“确认、可以生成、按此制作”等，才进入下一步。

## 5. 生成并验证 PPT

确认后使用 `Presentations` 技能创建 PPTX，并完整遵守其内容质量、实现、模板跟随和 QA 要求。

- 公司模板：只使用登记的公司 PPTX 作为视觉来源，保留其字体、配色、页脚、版式和品牌元素；不与其他模板混用。
- 其他风格：按用户所选风格从零设计。
- 优先使用用户材料中的真实照片、图表和数据。确需外部事实或素材时先说明来源；不得把装饰性视觉置于准确性之上。
- 生成后渲染并逐页检查文字换行、溢出、遮挡、占位符、页码、图表口径和清晰度；修复所有非预期问题后再交付。
- 默认输出到当前任务工作区的 `outputs/`，文件名使用主题和日期；保留用户原始文件不变。

最终回复只给简短说明和一个可点击的最终 PPTX 链接。

## Token 控制

- 每轮最多 3 个问题；已有答案不得重复询问。
- 先提取、后摘要；不把大段原文重新粘贴到对话。
- 用任务卡维护状态，用“页码 + 变化”处理修改。
- 未确认文稿前不运行模板分析、图片生成或 PPT 构建。
- 历史周报先筛选再读取，默认最多分析 2 份；用户明确要求全面对比时除外。
- 只在对应分支读取参考文件；不加载无关模板或说明。
