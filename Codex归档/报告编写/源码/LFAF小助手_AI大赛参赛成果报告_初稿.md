# LFAF小助手——非标自动化项目资料的AI智能检索与知识应用

## 一、项目概述

在非标自动化项目实施过程中，历史专案资料既是设计复用、异常处理和经验传承的重要基础，也是工程师解决现场问题时最直接的参考依据。然而，随着项目持续累积，资料数量不断增加，传统公共盘的层级式管理方式逐渐暴露出检索效率低、资料定位依赖个人经验、历史知识难以复用等问题。

针对这一痛点，LFAF提出业务需求，与IIC协同开发“LFAF小助手”。项目以部门历史资料为基础，通过AI提示词联想及知识库检索方式，帮助工程师更快速地找到相关资料。目前，小助手已完成整体架构搭建和小程序开发，支持Excel、PPT等多种格式资料上传，并可根据使用者输入的提示词进行关联检索。项目后续将进一步引入AI总结分析和自动报告生成能力，推动部门资料从“存放在公共盘”升级为“可查询、可理解、可复用的知识资产”。

## 三、业务痛点：资料很多，但寻找困难

LFAF历史专案资料集中存放在公司公共盘，原有目录主要按照“年份—月份—专案”逐级建立。该方式便于资料归档，却不利于工程师按照问题或知识点反向查找资料。

当工程师需要查询某个报警代码、设备异常、历史方案或专案文件时，通常需要先回忆项目发生的年份和月份，再逐层打开文件夹，并在多个专案目录和不同格式的文件中逐一翻找。如果使用者不知道资料属于哪个专案，查找过程就如同“大海捞针”。

这一方式主要带来四项问题：

1. **查找时间长。** 工程师需要反复打开文件夹和文件，简单查询也可能演变成多轮人工排查。
2. **依赖个人经验。** 熟悉历史项目的人员查找较快，新员工或未参与原项目的人员难以定位资料。
3. **知识复用困难。** 报警处理经验和成熟方案已经存在于文件中，却可能因为无法被及时找到而被重复分析。
4. **经验传承存在风险。** 资料虽然保留下来，但知识仍分散在不同文件和个人记忆中，尚未形成便捷的部门知识入口。

## 四、AI应用流程及作用

LFAF小助手将原本“依赖目录路径查找资料”的流程，转变为“从问题或关键词出发查找资料”。其业务流程如下：

**历史资料上传知识库 → 系统处理多格式文件 → 工程师输入问题或提示词 → AI进行提示词关联与资料匹配 → 返回相关资料线索 → 工程师查看并确认原始资料。**

AI在该流程中的核心作用是连接“工程师的自然表达”与“历史资料的存储内容”。使用者不必准确记住文件名、年份、月份或专案路径，只需输入报警代码、设备名称、异常现象或相关关键词，小助手即可通过提示词联想帮助缩小检索范围。

以目前使用较多的报警代码查询为例，传统方式是先判断报警可能出现在哪个项目，再进入公共盘逐层查找电气资料、调试记录或说明文件；使用LFAF小助手后，工程师可以直接以报警代码作为查询入口，快速联想到可能相关的历史资料。AI由此承担了“资料导航”和“知识入口”的作用，工程师则保留对原始资料和处理方案的专业判断。

> 注：知识库解析方式、模型类型、索引机制及检索技术细节由IIC负责，正式参赛前需由IIC补充确认，避免在报告中作未经验证的技术描述。

## 五、已实现成果

目前项目已经实现以下基础成果：

1. 完成LFAF小助手整体架构及小程序开发；
2. 建立部门资料进入知识库的应用入口；
3. 支持Excel、PPT等多种格式文件上传；
4. 支持基于使用者输入内容进行提示词联想和资料查找；
5. 已形成报警代码查询这一高频、明确的应用场景；
6. 初步验证了AI辅助工程资料检索的可行性。

项目的价值并非简单地把公共盘“搬到另一个系统”，而是改变资料的访问方式：过去必须知道“资料放在哪里”，现在可以从“我要解决什么问题”出发寻找资料。这使沉淀多年的专案文件有机会转化为可持续利用的部门知识。

## 六、成果价值测算

由于目前尚未完成统一的效率统计，以下数据为参赛报告的**情境测算值，不代表实测成果**。

假设人工在公共盘完成一次报警代码或历史资料查询平均需要15分钟，使用小助手完成关键词输入、资料定位和结果确认平均需要2分钟，则单次查询可节省约13分钟，查询时间缩短约86.7%。

年度节省工时可按以下方式估算：

**年度节省工时＝部门日均查询次数 × 13分钟 × 220个工作日 ÷ 60。**

例如，若部门平均每天发生10次类似查询，则理论上每年可节省约477小时。该测算尚未包含因快速复用历史方案而减少的重复分析时间，也未计算新员工学习和经验传承方面的间接收益。

为形成可信的比赛数据，建议赛前选择20至30个常见报警代码或典型资料查询任务，分别记录人工查询和小助手查询的用时、是否找到正确资料及使用者评价，形成以下三项指标：

- 平均查询时间及时间缩短比例；
- 首次查询成功率或正确资料命中率；
- 试用人员满意度。

正式汇报时应优先使用实测数据替换上述情境测算值。

## 七、项目创新亮点

### 1. 从目录检索转向问题驱动检索

传统公共盘以文件存储位置为中心，LFAF小助手以工程师的实际问题为入口，使资料查询不再依赖对年份、月份和专案目录的记忆。

### 2. 将AI嵌入真实工程场景

项目不是脱离业务的AI功能展示，而是围绕报警代码查询这一高频场景落地。AI直接参与工程师“发现问题—寻找资料—参考历史经验”的工作流程。

### 3. 建立多格式资料的统一知识入口

非标自动化资料分散在Excel、PPT等不同文件中。小助手通过统一入口连接多种格式资料，为后续跨文件检索、总结和分析奠定基础。

### 4. 推动个人经验向部门知识转化

历史项目经验不再只依赖参与人员记忆，而是通过知识库向更多工程师开放，有助于降低人员经验差异带来的查询门槛。

### 5. 具备持续扩展能力

当前项目从搜索和提示词联想切入，后续可逐步扩展至内容总结、方案比较和报告生成，形成“资料检索—知识理解—内容输出”的AI应用链路。

## 八、后续规划

项目下一阶段将重点发展AI自动总结和报告生成能力。计划方向包括：

1. 对单个专案的方案、调试和验收资料进行自动摘要；
2. 汇总报警代码、异常现象、原因及历史处理方式，形成可复用的故障知识；
3. 根据指定主题跨文件归纳资料，辅助形成技术说明或项目复盘；
4. 基于固定模板自动生成项目报告初稿，并由工程师审核确认；
5. 建立资料分类、版本、权限和更新机制，提升知识库内容的准确性与时效性。

后续升级的目标不是取代工程师作出专业判断，而是让AI承担资料查找、内容汇总和初稿整理等耗时工作，使工程师把更多精力投入方案设计、问题分析和技术决策。

## 九、总结

LFAF小助手源于非标自动化部门真实而普遍的资料查找痛点。项目通过LFAF与IIC协作，将AI提示词联想和知识库能力嵌入资料查询流程，初步实现从“逐层翻找文件夹”到“围绕问题寻找资料”的转变，并以报警代码查询形成了可展示、可验证的应用场景。

当前成果证明了AI辅助部门资料检索的可行性。随着资料持续入库、实测数据积累以及自动总结和报告生成能力的加入，LFAF小助手有望进一步降低资料查询成本、促进历史经验复用，并为公司其他资料密集型部门提供可复制的AI知识应用模式。
